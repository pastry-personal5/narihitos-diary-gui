# Editing and agents

Status: Active

This defines client state ownership, paragraph review and runtime-selectable agent adapters. The [canonical UX](../ux-gui.md) governs visible behavior; the [API](api-and-processes.md) carries validated use cases.

## Editor and client state

React owns layout, active date/tab, focus, snippet inclusion, command availability and rendered status through reducers/context. A dedicated CodeMirror module owns one EditorState per resource ID, including undo/selection/scroll and extensions. Use one active EditorView and switch retained states; destroy the view/subscriptions on unmount. Keep streamed text and keystroke document storage outside global React state. Client application state machines depend on a typed bridge port; Vitest can use a fake without loading Tauri.

Draft and Entry both resolve `AuthenticId`/date to the same buffer, view state and ordered save queue. Source buffers have explicit Save and a base observation token. Candidate buffers are read-only, transient and never eligible for save/export as Authentic. A focused snippet opens its buffer independently of its checkbox; checking it changes only generation inclusion. Multiple Explorer paths to one resource activate its existing buffer/tab rather than create competing editors.

Authentic save states are `clean`, `dirty`, `saving`, `save_failed`, `external_conflict`; source states add unsupported/read-only capability. Date/tab/close transitions guard all buffers they would discard. Date change waits for pending Authentic saves and resolves dirty source buffers; switching ordinary editor tabs preserves states and does not discard pending edits. Explicit discard warns about loss and returns to the last observed saved body. A network timeout queries the original operation before retry; do not create duplicate saves.

One command registry routes toolbar, native menu, palette and keyboard shortcuts to the same state transition. Local Cmd+Shift+P opens the command palette; Cmd+S explicitly saves sources or flushes Authentic. Keyboard composition suppresses app shortcuts that would interrupt IME. Pane resize supports keyboard and pointer, visible focus and minimum editor/control sizes; restore focus to the invoking control when a dialog/palette closes. Native icon buttons always have canonical accessible names and text tooltips. Use native checkbox/group/disclosure semantics for the grouped snippet hierarchy rather than incomplete ARIA tree semantics.

## Paragraph alignment and review

Start review only after the Authentic queue is clean and the server has verified its current revision matches the chosen candidate's captured generation baseline. A changed baseline requires regeneration, not an implicit rebase. A review binds `{session, authentic_id/date, baseline_revision, baseline_body, candidate_id, candidate_body, rules_version:1}`. Represent an absent baseline as a virtual empty revision until the first accepted insertion; starting review writes no file. The chosen candidate has already passed output validation and belongs to that session/date. Pending suggestions live in memory; manual editing of this Authentic buffer pauses until review ends. Source editing remains independent.

Alignment rule 1 uses lossless Markdown source ranges, not rendered HTML or sentences. A prose paragraph is one review unit, including its hard/soft wrapped lines. A heading, list item with continuation/nested content, blockquote paragraph, fenced code block, or table is an indivisible structural unit; blank separators attach to the preceding unit, with initial whitespace retained as a prefix unit. Never split a fence/table into unrelated lines. Such structures are visibly labeled in the review so a paragraph decision cannot silently edit half a structure. If the tokenizer cannot preserve exact source spans, reject review as unsupported instead of falling back to whole-file replacement.

Compute a longest common subsequence of byte-exact unit text; choose earliest baseline index then earliest candidate index for ties. Unchanged units are anchors. Within each differing region pair baseline/candidate units by order: each pair is a single replacement decision, remaining baseline units are individual deletions and remaining candidate units are ordered insertions at that boundary. Stable hunk IDs include rules version, baseline/candidate digests and unit positions. Cap combined unit count at 4,000 and alignment work at 4 million comparisons; larger/ambiguous-to-tokenize documents return a visible review-limit error, never silently switch adoption mode.

Example: baseline `[A, B, C]`, candidate `[A, B2, X, C]` produces replacement `B→B2` and insertion `X` before C. Accepting X alone saves `[A, B, X, C]`; rejecting B2 leaves B. For deletion `[A, B, C]→[A, C]`, accepting the B deletion removes only B. Repeated paragraphs use the deterministic tie rule. Trailing/leading whitespace changes are explicit units/parts of replacements; reconstructing all accepted hunks must equal candidate bytes exactly.

Every unit decision is `pending`, `accepted` or `rejected`. Recompose from the immutable baseline plus accepted hunks in original order, not by applying shifting character offsets to the current editor. Accept one hunk at a time through the server, with current review revision, durable operation ID and expected prior accepted-set digest. The server recomposes the same result and publishes via normal Authentic save. Its durable result records the hunk, resulting revision and before/after accepted-set digests in the same transaction as the save receipt; only then update memory and acknowledge acceptance. A lost reply is resolved by `get_operation`/the original operation ID before checking a missing review or stale revision. Within a live review, replaying that committed result repairs memory only when the current set matches its before-digest; it never regresses later accepted decisions or publishes again. After restart, the saved body/result is recoverable while the transient review remains gone.

Serialize accepts, rejects and end-review against the same review/resource coordinator. End-review, regeneration and date/close transitions wait for admitted accepts to settle or become explicitly uncertain; discarding a pending suggestion cannot retract an already admitted write. A failed accept retains the saved accepted set and offers retry/discard of the pending action. An uncertain accept requires operation reconciliation before another decision or manual save. Rejection writes no file. Hunk states cannot be toggled after commitment; subsequent manual correction uses normal editing after ending review.

The baseline stays fixed while expected saved revision advances for the review's own accepted writes. Any unrelated local/server/external revision change invalidates remaining suggestions; accepted text stays saved. Do not silently rebase. Ending review discards pending hunks and resumes editing. Leaving a date ends its active review after admitted accepts settle and discards pending hunk decisions; background generation and completed candidate results remain session-owned and attached to their original date. Returning may reopen those candidates, but stale baselines remain ineligible for review. Client close cancels agent runs and discards all transient reviews/candidates after the save/cancel guards. Server restart loses review/candidates; the last acknowledged accepted paragraphs survive. Regeneration ends the old review after admitted accepts settle and creates new candidates against a newly captured saved baseline.

## Agent port and profiles

The application owns `AgentRunner`: `check(profile) -> ProfileStatus`, `run(AgentRequest, event_sink, cancellation) -> AgentResult`. `AgentRequest` includes mode, immutable context, schema version, limits and selected profile handle; no frontend command strings. Codex, Claude Code, Qwen Code and Apple Foundation Models implement this same port. CLI adapters use one-shot processes for chat turns and each candidate; Apple uses a fresh native model session per run. Persistent model sessions across turns and direct cloud-provider APIs are outside this design. Selecting another alias starts a new chat session or generation; never silently switch profile/model after a failure.

Profile states distinguish `missing`, `unsupported_version`, `unavailable`, `available_auth_unknown`, `unauthenticated`, `ready`, `busy`, `failed`. Read version/status only through verified non-inference checks, bounded to 5 seconds. Never read/copy login files or use a model turn as an auth probe. A missing optional CLI or unavailable system model disables only that profile. CLI adapter compatibility starts with exact versions/protocol fixtures from [agent research](../research/agent-assisted-diary-composition.md); unknown versions remain unsupported until checked, rather than assuming a universal minimum-version comparison proves compatibility.

| Adapter | One-shot protocol family to validate | `profile_home` environment variable | Default binary on `PATH` |
|---|---|---|---|
| Codex | `exec`, stdin prompt, NDJSON and output-schema file | `CODEX_HOME` | `codex` |
| Claude Code | print mode, stdin prompt, stream JSON and JSON Schema | `CLAUDE_CONFIG_DIR` | `claude` |
| Qwen Code | headless stdin, stream JSON and JSON Schema | `QWEN_HOME` | `qwen` |

CLI profiles configure the selected home with `agents.profiles[].profile_home`. An optional `executable` overrides the default binary lookup in the server's launch `PATH`; resolve the chosen executable to an absolute path before checks or runs, following the [configuration contract](configuration-and-exports.md#configuration-schema-and-validation). An omitted override is valid; an unavailable executable or profile home disables only that profile. Apple profiles use neither CLI setting.

Concrete flags belong to versioned adapter fixtures; the research records inspected versions and limitations. Do not generate a command line by concatenating user text. Provide schema via a private run file only when the protocol requires it; prompt text goes on stdin. No runtime dependency on a particular installed agent.

## Apple Foundation Models adapter

`apple-foundation-models` selects Apple's on-device system language model through a server-owned native adapter. Apple's [Foundation Models guide](https://developer.apple.com/documentation/foundationmodels/generating-content-and-performing-tasks-with-foundation-models) describes `SystemLanguageModel.default`, `LanguageModelSession` and the required availability check. The adapter checks the supported OS/framework and model availability without inference, then rechecks before each run. Redacted unavailable reasons distinguish unsupported OS, ineligible device, Apple Intelligence disabled, model not ready and unknown unavailability. Availability does not require a CLI login, profile directory, executable, API key or cloud account probe.

Internal design: keep the Swift framework boundary in infrastructure behind `AgentRunner`; the application and WebView receive only the existing typed requests/events/results. The concrete native binding or helper, SDK/toolchain and build integration require the normal approval before adoption. This design does not establish packaged Rust/Swift interoperability. No arbitrary native calls, tools or filesystem operations are exposed to the model. Inference uses the selected on-device model; there is no automatic cloud or CLI fallback.

Each admitted chat turn or candidate creates a fresh session with asset-loaded instructions and the immutable context. Chat still resends its memory-only transcript. Generation maps guided output to the same closed generation schema and applies the common validation/review rules; do not use the supplied template fields as an alternate output contract. Apple does not receive model or reasoning-effort overrides. The OS can update the system model, so acceptance records OS/SDK and available model metadata rather than claiming a pinned model version.

Map context exhaustion, unavailable assets, unsupported language, refusal/guardrails, rate limiting and decoding failure to redacted typed outcomes. Apple's [error reference](https://developer.apple.com/documentation/foundationmodels/languagemodelsession/generationerror) varies by SDK; validate the actual error API for the approved build. Context failure offers reduced selection or a new chat; never silently truncate, summarize or retry through another provider. The common byte bounds are upper bounds, not a promise that the native model accepts that much input.

## Prompt assets

All app-authored instructions come from `assets/prompts/<agent-type>/`; the [asset contract and inventory](../../assets/prompts/README.md) define metadata, substitution and current gaps. Inspect and reuse existing files before writing new prompts. Load and validate them in infrastructure, including session, task, style and any approved repair instructions; no prompt prose or fallback prompt belongs in source code. Missing/invalid assets disable the affected action visibly. A template's presence does not establish schema compatibility, approve additional workflows or authorize hidden extra calls.

## Context, output and limits

Generation requires at least one selected eligible snippet; otherwise Generate is disabled with a visible explanation. The server independently rejects an empty selection before inference. Capture selected observations after checking their bytes remain current; dirty source buffers must first be saved or explicitly excluded. Timestamp conflicts/unknown dates are ineligible. Order resolved instants/path keys deterministically. Each packet item contains an opaque `snippet-1` label, its resolved UTC instant, captured-zone civil date/offset and body text; omit filesystem paths, raw front matter, location and audio. These validated date fields supply the adjacent-day labels that the prompt needs. Bind generation to the selected DiaryDate, captured import context and saved baseline revision/digest. Warn when the packet contains adjacent dates so instructions use their labels rather than inventing a timeline. Dirty Authentic content must be flushed before binding the generation baseline.

Writing language is a [persistent user setting](user-settings.md), initially the Mac's preferred language, selected in Settings and reused across client sessions. The bridge includes its validated BCP-47 locale in each new chat/generation request; the server validates it and substitutes `{{locale}}` from that immutable run snapshot. A later preference change affects new runs, never an in-flight prompt. Do not infer writing language from timezone or source text.

Changing the selected date does not cancel generation. The background job keeps its captured date, import observations, locale, profile and Authentic baseline; changing checkboxes, re-importing or editing another date never retargets it. Progress and completion identify the original date, and completion does not switch the active editor or insert text automatically. Keep candidates available for that date during the session. The one-agent-run limit still applies across dates: another chat/generation is busy until the background run finishes or the user explicitly cancels it. Close, lease expiry and server shutdown retain their cancellation rules. **Create Empty** is independent manual creation and remains available without source selection or an agent, subject to the normal absence/save guards.

The [background AI experience](ai-job-experience.md) defines immediate submission feedback, truthful stages/elapsed time, provisional previews, completed-candidate counts, in-app completion attention and accessible cancellation. Generation does not pause manual editing. If that date's saved Authentic changes, candidates remain readable but require regeneration before review; the owner selected this instead of reviewing against a new baseline. A job store independent of editor mounts preserves off-date progress without unbounded React updates.

One selected profile generates candidates sequentially, default 3, adjustable integer 1–5. Use deterministic style hints in order: standard, concise, reflective, chronological, thematic, preserving facts/uncertainty for every style. Style identifiers are data; their instruction wording lives in prompt assets. One model call per candidate; no hidden extra summarization or automatic retry/fallback. A failed candidate does not remove completed candidates; proceed with the remaining admitted count unless cancelled. Only one active agent run per client, including native sessions, so concurrent chat/generation requests receive `busy` and can be retried explicitly.

Generation JSON schema 1 is a closed object with `draft_markdown` (string), `claim_support` (array of `{claim:string, snippet_ids:string[]}`), and `warnings` (string array). Require known nonempty snippet IDs for every support entry, at most 2,000 support entries with 2 KiB claims/at most the selected snippet count per ID list, and at most 100 warnings of 2 KiB each. Bound the complete encoded result to 8 MiB in addition to the 1 MiB UTF-8 draft limit. Require no front matter in the draft, a valid final result, successful process exit for CLI runs or successful native completion, and no terminal adapter error. Reject malformed/extra-schema/oversized outputs without extracting a fenced free-text fallback. Support annotations are an audit aid, not factual proof. A candidate is reviewable only after final validation; partial streaming text is labeled provisional.

Chat snapshots the active editor body including its current unsaved edits, labels resource type/date and unsaved state, and resends the transient transcript on each run. No active document means no document context. Do not include front matter, unrelated tabs or selected snippets unless they are the active context. Profile remains fixed for that chat session. App transcripts are memory-only and erased on explicit close/lease expiry/server exit; CLI/provider records are separate.

Engineering bounds: 256 KiB complete encoded input packet, 64 KiB per user message, 100 transcript messages/128 KiB transcript, 1 MiB final draft, 10 MiB total stdout+stderr, 1 MiB per protocol record, 120-second inactivity and 10-minute wall deadline per run. Exceeding a bound fails visibly with `context`/`invalid_output`/`timeout`; never silently truncate diary/chat input or delete old turns. Offer a new chat or reduced selection. Usage is reported only when the adapter supplies it; these limits do not promise a universal money/token budget.

## Trust and process lifecycle

The following environment, pipe and process-group rules apply to CLI processes and any approved native helper. For an in-process native session, propagate cancellation to its task and wait for a terminal outcome before admitting another run; enforce the same inactivity/wall deadlines and cancellation epoch. Lease expiry, close and server shutdown cancel native work too. Reject late results after committed cancellation and release the transient session. A helper must also satisfy the process supervision rules below. Native cancellation and cleanup require actual evidence before enabling the profile.

The owner trusts the installed CLI's normal access, account and configuration, including its tools/hooks/MCP. No confinement or retention guarantee is implied by empty cwd, data delimiters or filtering. Use an owner-private fresh working directory outside sources/workspace/config, minimize app-provided context and never inherit the server's complete environment. Allow system essentials (`HOME`, controlled `PATH`, locale, required OS temp/runtime values), the selected CLI home variable and validated profile-specific nonsecret settings only. Notion/API credentials are never environment variables passed to agents. The literal credential remains readable by a trusted same-user CLI through its normal filesystem access; this policy cannot prevent that.

Use the absolute executable resolved from the optional override or type-specific `PATH` default, fixed argv arrays and a new process group, no shell. Concurrently drain stdout/stderr, validate streaming records and bound retained diagnostics; logs contain only job IDs, counts/status/durations. Do not log prompts/responses/paths/raw stderr. Best-effort app-created temp cleanup is separate from CLI/provider retention; normal CLI configuration is not claimed suppressed. App files contain no persistent transcript.

Cancel, timeout, lease expiry or server shutdown marks the run stopping, closes stdin, sends TERM to the process group, waits 2 seconds then KILL, reaps and drains pipes for at most 1 additional second. Ignore late deltas/results after the cancellation epoch; success must not race a committed cancel. Do not schedule another run until supervision reaches a terminal state. Descendants escaping the group require verified native supervision or a profile-specific unsupported outcome; killing only the direct child is insufficient. On unclean server death mark old durable job handles interrupted; do not signal a recycled PID during recovery. No promise of cleanup after SIGKILL without native evidence.

## Required evidence

Vitest must exercise shared Draft/Entry state, independent focus/checks, IME-aware flush, old acknowledgements, close failures and stale events. Domain fixtures must exercise alignment insert/delete/repeated paragraphs, structures, exact byte reconstruction, serial accepts/rejects, restart and external invalidation. Fake CLIs must cover split records, malformed final output, auth errors, flooding stderr, escaped descendants, hangs and cancellation. Real CLI compatibility/schema/auth behavior and synthetic macOS process-tree cleanup remain required before enabling each CLI profile. Trusted access removes a confinement prerequisite; it does not establish successful execution or vendor policy permission.

Native adapter fixtures must cover every unavailable reason, availability loss mid-run, bounded fresh-session chat/generation, guided-schema rejection, context/language/refusal errors, cancellation/deadlines and late-result suppression. A synthetic live run on the owner's Mac with the actual packaged server/native bridge must establish availability, schema mapping and cancellation before enabling Apple Foundation Models. Asset checks must cover front matter, missing/malformed files, single-pass substitution (including diary text containing placeholders), release packaging and prompt/output-schema compatibility for every enabled action. Supplied templates alone satisfy none of these runtime checks.
