# Sources and dates

Status: Active

Imported snippets are views of configured originals, with explicit guarded source saving and Trash deletion. This document defines path identity, metadata/date rules and the conditional producer-compatibility boundary.

## Path identity and observations

An identity is the tuple `(canonical source-root path, normalized relative Markdown path)`, not alias, producer ID, content digest or inode. Resolve configured roots once with filesystem canonicalization and inspect volume case behavior. Require UTF-8 paths; normalize components to Unicode NFC, and case-fold for comparison only on a case-insensitive volume. Retain actual filesystem spelling for I/O. Relative paths have `/` separators, no empty/`.`/`..` components or absolute prefix. Two distinct directory entries collapsing to the same key are a visible `path_collision`; neither can be mutated/generated until resolved. Do not guess a winner.

Reject duplicate/nested source roots and two aliases resolving to the same root or physical directory. A configured symlink alias of the root canonicalizes to that same namespace; symlinks below the root are not followed. Hard-linked files at distinct valid paths remain distinct path identities, but writes/deletes require link count 1. Device/file IDs are freshness/alias guards only. Root/path renames on disk produce new identities when their normalized path changes; case-only/Unicode-equivalent renames on the same insensitive volume do not. Changing the display alias preserves identity; moving the configured root does not. A case-sensitive volume retains case distinctions. Pin supported volume behavior in filesystem tests.

The public `source_id` is an opaque encoded/hash key bound to this tuple; it stays stable across configuration reloads, and the config generation is bound by the observation token instead. Hash collisions must be checked against the stored tuple. Re-import upserts the same identity, leaves unchanged entries visible/selected, and refreshes changed clean views. New eligible snippets start checked only when their local date is the selected day D; D-1 and D+1 snippets start unchecked. Missing or changed selected observations are visibly invalidated; do not silently include new bytes in an already prepared generation. A dirty source buffer keeps its base observation and local text until explicit save/reconcile/discard. No durable editable imported copy is created. Cached body text lives only in bounded memory.

Fresh reads open a regular file beneath the validated root with no symlink traversal, bound bytes before allocation, inspect metadata before/after reading and hash complete bytes. Retry an unstable read once; then report `source_changing`. Observation tokens bind source tuple, digest, native file identity, size, config generation and import context. Roots are revalidated at each mutation, including replacement/symlink swaps. File-not-downloaded, denied, missing, malformed, unsupported and conflicting are distinct outcomes; one failed file does not discard valid neighbors.

A scan returns, per file, exactly one outcome class: `ok`, `unavailable` (missing, denied, not downloaded), `malformed`, `unsupported` or `conflict`; plus scan-level `path_collision` groups and an `incomplete` flag. An `unsupported` file keeps its body viewable. An `ok` view carries one dating state: resolved instant, `timestamp_conflict` with both interpretations, or undated. A scan returns body-less listings; bodies are read on demand and must match the listing's token. Outcomes and tokens carry relative keys and codes only, never absolute paths, body text or front-matter values.

## Parsing and timestamps

Separate Ayumi and Narihito adapters dispatch from `sources[].type`. Accept UTF-8 Markdown up to 8 MiB total, front matter up to 64 KiB/64 keys/8 KiB scalar, and editor body up to 1 MiB. Reject duplicate keys, YAML aliases/tags, excessive nesting, malformed encoding and stray CR. Accept a BOM and consistent CRLF for reading; preserve those conventions for supported source saves. Bound scanning to 10,000 candidates per import and report incomplete/limit reached instead of silently presenting a partial list as complete. Larger trees require a later bounded scan continuation.

Retain raw front matter and original serialized timestamps in the adapter observation. The editor shows the body, including attachment syntax, as plain Markdown source; no preview or attachment fetching. Agents receive body text with adapter-recognized attachment-only lines removed and opaque snippet labels; unknown lines remain text. Do not rewrite body contents during import. Unknown scalar metadata is preserved. Supported producer details and coverage limits come from [source research](../research/source-formats-and-prior-art.md).

Validate header creation instant and UTC filename/directory timestamp independently. Header offset must be explicit; never interpret a naive timestamp using the current timezone. Compare at the precision actually encoded by the filename: second-resolution filenames compare whole seconds, millisecond names compare milliseconds. Reject impossible calendar values. Directory date must agree with the filename UTC date. If valid evidence disagrees, list `timestamp_conflict`, show both interpreted instants and exclude from automatic date assignment/generation until explicitly resolved. Scan-time path discovery must not hide an unresolved conflict; include a separate warning list for scanned conflicting files.

Resolution offers the two valid authorities, header or filename, in the metadata warning UI. Persist the explicit choice keyed by path identity plus complete-byte digest; do not modify source metadata as a side effect. If only one authority is valid, still require explicit choice of that valid value; if neither is valid the source remains undated/readable and generation-disabled. Filename/directory conflict must be corrected externally before choosing filename. A byte change invalidates the resolution. Missing/malformed/unknown schema may allow bounded body viewing but never an inferred timestamp or source write. Producer IDs may warn on duplicates but never deduplicate paths.

## Import zone and calendar boundaries

`import_date(D)` captures the server system IANA zone and timezone-database version once, before scanning. Failure to obtain a named zone is an error, not a guessed fixed offset. Calendar arithmetic forms D-1, D and D+1; inclusion converts a resolved snippet instant into that captured zone. The source offset is provenance. Later travel/system-zone change requires a new import context; old observations and saved Authentic dates never silently shift.

Define start-of-day as the earliest real instant belonging to the civil date. For a repeated midnight choose its earlier occurrence; for a midnight gap choose the first valid instant on that date. If selected D is an entirely skipped date, report `invalid_diary_date`. A skipped neighbor contributes no instants. The scan interval spans the earliest valid start on/after D-1 through the earliest valid start on/after D+2, half-open. Compute intersecting UTC directory dates as calendar evidence, but scan all configured source directories within the shared candidate/entry/metadata bounds before filtering actual converted dates to the three-date set. Never add 72 elapsed hours or reuse today's offset. Within that set, order by resolved instant then canonical source/path key for deterministic ties.

Date imports do not prune discovery by directory date: misplaced files can carry in-window header evidence even when their directories fall outside the UTC interval. Such files remain visible as warnings and require explicit authority resolution. Whole-tree discovery keeps the same shared bounds; hitting a bound reports incomplete coverage instead of claiming every misplaced file was found. Canonical Rust date logic supplies ISO civil fields to React; calendars do not pass date-only strings through JavaScript `Date`/UTC. Existing Authentic date metadata is immutable, including when saved after midnight or re-imported in another zone.

## Explicit source saves

Source Save submits the body plus the whole-file SHA-256 digest of the file the client last read or saved (`base_digest`), never a replacement header or frontend path. Admission rests on the durable source-id binding and a validated configured root, not on an import snapshot or `config_generation`; the server re-reads the file inside the write accessor and refuses a differing digest as `external_change`. The response carries the next digest, so the immutable snapshot is never consulted or updated. Preserve raw unknown metadata, field order/comments, attachment references and producer-required identity/creation/audio/transcription fields. Only the adapter may update a producer-required `updated_at`, formatted at its required precision with a value later than the previous value (previous + 1 s when the clock has not passed it, as the producer's own edit does). For the inspected mobile schema this is whole-second UTC, written only through a producer-strict per-file gate (LF only, no BOM, exact `\n---\n\n` close, producer key/scalar grammar) after which the editor body excludes the producer's blank separator line and the save restores it; `title` and `title_origin` are copied unchanged (owner decision, 2026-11-06); do not fabricate title/provenance/audio hashes or advance producer-specific catalog revisions from guessed semantics. Ayumi updates remain disabled without its producer contract. Any required coordinated metadata/catalog update must be part of the verified adapter operation.

Each source adapter advertises independent `read`, `write_body`, `trash_pair` capability and supported schema/producer version. Both mutation capabilities default disabled. Required enablement evidence is a synthetic producer round trip: GUI save → producer load/reopen/update and producer write → GUI re-read, including unknown fields, changed body/updated_at, audio integrity, producer catalogs/recovery and concurrent edits. Unsupported variants remain readable where parsable with Save disabled. Successful text parsing alone never enables a writer.

For an enabled writer use the durable intent/stage/publication protocol from [persistence](domain-and-persistence.md), preserve file mode, and coordinate access with the verified producer/native mechanism. Revalidate base bytes and ownership immediately before publication; detect post-write divergence and enter conflict. An active incompatible producer/uncoordinated writer or unavailable placeholder makes mutation unavailable. Never promise an atomic cross-application CAS from check-then-rename. Recovery must inspect both source and any producer-owned companion state before retrying; never roll back new producer bytes.

## Related audio and Trash

Trash preview derives members in Rust. The inspected mobile mapping permits only the validated sibling `<stem>.assets/<uuid>.m4a` tied to matching source identity/audio metadata. Other formats need an equally explicit adapter ownership contract. No wildcard `.assets` deletion, arbitrary Markdown-link following, directory recursion or all-sibling removal. Verify containment, regular-file kind, no symlinks/hard links, complete fresh digest/native identity and absence of a shared reference; ambiguous ownership disables deletion. Missing expected audio is shown as missing, not claimed moved; unavailable cloud content blocks confirmation. A preview lists snippet and validated related audio without deleting an empty/unrelated directory.

A one-use preview token expires after 60 seconds and binds session, config, exact member set/digests and source observation. Initial confirmation creates a durable operation and its [confirmation step](api-and-processes.md#wire-types-and-preconditions) only after revalidation; changed members require a new preview/confirmation. Reserve the source and every validated audio member against competing save/Trash actions. Atomically record token consumption, authorized step and member intent before invoking native Trash. Move the Markdown first to avoid leaving a live snippet pointing at already trashed audio, then each validated audio member; if moving the Markdown fails or is uncertain, do not proceed to audio. Record the native receipt after each result. Cross-file Trash is not atomic: report each moved/missing/failed/uncertain member and preserve the operation for retry. Duplicate confirmation returns the existing step outcome even after its token was consumed.

If a crash loses a Trash reply, reconcile using the native operation receipt/resource identity. Original-path absence alone cannot prove it reached Trash. If provenance cannot be established, mark `uncertain` and require explicit inspection; never delete a replacement file or silently retry that member. Recoverable per-member failures leave the operation in `needs_confirmation` with a partial result, rather than a terminal state that could later resume. Retry addresses only failed unchanged members under renewed confirmation, the original operation ID and a new step ID/checkpoint; completed members stay completed. A replacement snippet at the original path is not the original member and cannot be removed by an audio-retry continuation. Restoration, permanent deletion and deletion of producer catalogs are outside this contract. Mutations remain disabled until native Trash, producer reopen, per-member interruption, duplicate confirmation and partial-retry fixtures pass on macOS. The [P1-M15 owner decision](../archive/milestones/p1-m15/milestone-15-source-audio-trash-architecture.md#owner-decisions) requires this evidence through automated tests/harnesses plus the full gate; human testing is not an enablement or exit gate, including as deferred P1-M15 acceptance at P1-M32. Unverified device/cloud behavior remains an evidence limit.

## Implementation status

P1-M9 implements read-only library adapters and bounded scans; [acceptance evidence](../archive/milestones/p1-m9/milestone-09-source-reading-overview.md#evidence-record) records synthetic coverage and provider/mount limitations. P1-M10 adds captured-zone date imports, immutable SQLite provenance, digest-bound authority choices, HTTP routes and three typed Tauri commands; the [completion record](../archive/milestones/p1-m10/milestone-10-civil-date-imports-overview.md#evidence-record) records synthetic and real-server evidence. The Explorer and resolution UI were delivered in P1-M11, and P1-M14 separately enabled supported source body saves. P1-M15 implements bounded pair preparation, confirmation, durable member execution/recovery and typed transport. Narihito schema 1 Trash is enabled after automated native interruption and pinned producer catalog/reopen evidence; Ayumi stays disabled. Empty assets directories remain: the pinned producer reports a `changed` recovery row with no text/audio after full deletion. Synthetic local macOS evidence does not verify phone/live-iCloud behavior. See the [completion evidence](../archive/milestones/p1-m15/milestone-15-source-audio-trash-overview.md#implementation-evidence).

On macOS, each import reads `/etc/localtime` afresh, resolves a named zone inside the canonical system database and records its `+VERSION`. No process timezone cache or shell `TZ` override replaces the configured Mac zone. Unknown/unreadable zones and versions fail. A completed import atomically publishes an immutable, body-less SQLite snapshot with its completion marker. Listings read that snapshot without scanning sources or reloading timezone rules, so pagination survives source edits, removals, system-zone/tzdb changes and server restarts. Snapshots retain observation tokens internally; responses expose the import ID, digest and relative identity without native file identifiers or source bodies. Each encoded snapshot is bounded to 16 MiB in addition to the shared scan bounds; exceeding the encoded bound fails publication with `limit`, without completing the context. Snapshots are not silently evicted.

A new import is the explicit refresh boundary. Timestamp resolution locates the selected snapshot identity and freshly re-observes only that source, validating root, path, full observation token and config generation before storing the digest-bound choice. Existing snapshot ordering/classification remains fixed; a new import applies the choice and reflects changed/missing/new files. Completed contexts from before snapshot support return `source_stale` and require re-import, rather than being silently reconstructed. The [hardening record](../archive/milestones/p1-m10/milestone-10-import-hardening-overview.md) supersedes the original record's fresh-listing and old-tzdb failure limitations.

## Required evidence

Use synthetic fixtures for both producer schemas, BOM/CRLF, limits/unknown metadata, duplicate keys/IDs, source alias/move/rename/case/Unicode collisions, symlink/hard-link swaps, changed reads and dirty refresh. Date fixtures must compare complete inclusion sets across UTC/year/leap/non-hour offsets, 23/25-hour days, folded/skipped midnight and a skipped date, timezone changes and explicit disagreement resolution. Producer-compatible save/delete, live cloud coordination and native Trash are conditional capabilities; missing proof blocks those mutations while preserving supported reading and editing of local Authentic content.
