## Design decisions

**D1 Port (application, `agent` module).** Pure types, no I/O, no JSON.

- `AgentKind { Codex, Claude, Qwen, AppleFoundationModels }` with `asset_dir()` returning `codex|claude|qwen|apple-foundation-models`. Infrastructure maps each config `Profile` to `(alias, AgentKind)`; `ProfileHandle { alias, kind }` is the only profile reference a request carries. No command string, path or executable crosses the port.
- `ProfileStatus` is the eight-state enum: `missing`, `unsupported_version`, `unavailable`, `available_auth_unknown`, `unauthenticated`, `ready`, `busy`, `failed`.
- `trait AgentRunner { fn check(&self, profile: &ProfileHandle) -> ProfileStatus; fn run(&self, request: AgentRequest, events: &mut dyn EventSink, cancel: &CancelToken) -> Result<AgentOutput, AgentError>; }`. `check` is non-inference and its adapter bound is 5 seconds (enforced by adapters).
- `AgentRequest` is immutable after construction and holds: `schema_version` (1), `mode` (`Chat` or `Candidate { index, count, style }`), `profile`, `locale`, `limits`, and the typed packet from D3. `Style` is the closed enum `standard|concise|reflective|chronological|thematic`, in that deterministic order; its identifiers are data.
- `AgentEvent` is a closed enum: `Phase(Phase)` with `preparing_context|starting_agent|waiting_for_output|receiving_output|validating_output|between_candidates|stopping|finished` (the [ai-job-experience phase list](../architecture/ai-job-experience.md#ports-dtos-and-execution-isolation)), and `Delta(String)`. Adapters never supply a free-text phase label. Delta batching (50 ms / 16 KiB), progress counts and SSE belong to the job layer (P1-M21/P1-M22).
- `AgentOutput` is `Candidate(Candidate)` or `Reply(String)`. `Candidate { draft_markdown, claim_support: Vec<Claim { claim, snippet_ids }>, warnings }` is constructed only by the infrastructure validator (D4). A chat reply is plain text bounded by the same 1 MiB UTF-8 limit as a draft; the architecture sets no chat-reply schema or limit, so this reuse is an engineering bound to revisit in P1-M21.

**D2 Run guard and cancellation epoch.** `Run` wraps one admitted run. `Run::request_cancel()` commits cancellation exactly once and returns whether it was the first call. After a committed cancel, `Run::accept(event)` drops deltas and phases, and `Run::finish(result)` converts any success into `AgentError::Cancelled`, so success never races a committed cancel. Adapters call `finish`; the job layer owns admission. `CancelToken` is a cheap shared flag adapters poll or await. Limits live beside the port as constants: 256 KiB packet, 64 KiB user message, 100 messages / 128 KiB transcript, 1 MiB draft and reply, 8 MiB encoded result, 10 MiB stdout+stderr, 1 MiB per protocol record, 120 s inactivity, 10 min wall. M16 enforces the context and output ones; the process ones are consumed by P1-M17.

**D3 Request packets and locale.**

- `Locale::parse(&str)` accepts a BCP-47 shape only: ASCII letters, digits and `-`, 2–35 characters, subtags 1–8 characters, first subtag alphabetic. It rejects braces, spaces and empty subtags, so a locale can never carry a placeholder. It is a structural check, not a registry lookup (`shortcut: no IANA subtag registry; upgrade if an adapter rejects a structurally valid tag`).
- `GenerationPacket { schema_version: 1, style, target_date, snippets: Vec<SnippetItem { id: "snippet-N", instant_utc, civil_date, offset, body }> }`. The constructor rejects an empty selection (`context`), duplicate IDs and non-sequential labels. It carries no paths, raw front matter, location or audio. Bytes-current checks, dirty-buffer handling and eligibility are P1-M22's.
- `ChatPacket { schema_version: 1, document: Option<ChatDocument { kind: authentic|source, date, unsaved, body }>, transcript: Vec<Turn { role: user|assistant, text }>, user_message }`. No document means no document context. Constructors reject over 64 KiB user messages, over 100 turns and over 128 KiB transcripts with `context`, never truncating.
- The complete encoded packet (infrastructure `encode_packet`) is checked against 256 KiB after encoding, because the architecture bounds the encoded form. Over the bound is `context`.

**D4 Output validation (infrastructure `agent/output.rs`).** `validate_generation(bytes, snippet_count) -> Result<Candidate, AgentError>` parses with derived structs and `deny_unknown_fields` into the closed object `{draft_markdown, claim_support:[{claim, snippet_ids}], warnings}`.

- Rejected as `invalid_output`: unknown, duplicate or missing keys; a non-object; a fenced or prose-wrapped payload (no extraction fallback); a draft over 1 MiB, with leading front matter (`---` first line) or that is empty after trimming (an empty draft cannot be reviewed; **Create Empty** is the manual path); more than 2,000 support entries; a claim over 2 KiB; an empty `snippet_ids`, an ID that is not `snippet-N` with `N` in `1..=snippet_count`, or more IDs than `snippet_count`; more than 100 warnings or any over 2 KiB; encoded result over 8 MiB.
- Support entries are an audit aid and are not checked for factual truth. A candidate exists only after this function returns; streamed text stays provisional and is never an `AgentOutput`.
- Process success, native completion and the absence of a terminal adapter error are adapter conditions checked in P1-M17+.

**D5 Errors.** `AgentErrorCode` is the closed allowlist `busy`, `cancelled`, `timeout`, `context`, `invalid_output`, `unavailable`, `assets_unavailable`, `unsupported_language`, `refusal`, `rate_limited`, `failed`. `AgentError` holds a code and a static message and has no field for prompts, responses, paths or raw stderr, so it cannot leak content. Mapping vendor errors to codes belongs to each adapter.

**D6 Capability model.** `Action { Chat, Generate }`, `CapabilityReason { AssetsMissing, AssetsInvalid, AdapterUnimplemented }` and `Capability { Ready, Unavailable(CapabilityReason) }`. `capability(kind, action, assets, adapter_registered)` checks in order: any required asset invalid → `assets_invalid`; any required asset missing → `assets_missing`; no adapter registered → `adapter_unimplemented`; else `ready`. In M16 no adapter is registered outside tests, so Codex and Apple report `adapter_unimplemented` and Claude and Qwen `assets_missing`; `ready` is reachable only with a fake registration in a test. Nothing is exposed through the API (Q4). The existing startup `Availability` stays as is.

**D7 Prompt assets (infrastructure `agent/assets.rs`).**

- The embedded table is a `static` list of `(kind, name, include_str!(…))` for every shipped file. The loader takes the table, not a path, so it cannot read the working directory. `PromptAssets::embedded()` parses every entry into `Ok(Prompt)` or `Err(AssetError)` per asset; one bad asset never poisons the rest.
- Required assets per type: `generate-candidate` and `chat` for every type, plus `session-instructions` for `apple-foundation-models` (a native session needs instruction text separate from the task prompt; CLI profiles have one stdin prompt). Claude and Qwen have none yet, so each required asset is `AssetsMissing`.
- Front matter has exactly `provider`, `model`, `reasoning_effort`. `provider` must equal the type directory. Apple must be `default` / `not-applicable` (rejected otherwise). CLI types pass any non-empty single-line values through as strings; the loader never claims they are supported. Unknown or duplicate keys are malformed.
- Placeholders are `{{locale}}` and `{{data}}` only. Any other `{{`…`}}` or a stray `{{` is malformed. `generate-candidate` and `chat` must contain `{{data}}` exactly once and `{{locale}}` at least once; `session-instructions` contains `{{locale}}` and no `{{data}}`.
- `Prompt::render(locale: &Locale, data: Option<&str>) -> String` scans the template once and appends literal text or the matching value, never rescanning inserted values, so diary text containing `{{data}}` or `{{locale}}` is inserted verbatim. One trailing newline of the body is dropped, as the README states.
- Missing and malformed assets surface as `AssetError { kind, name, reason }` and then as the capability reason (D6). No fallback prompt and no use of another agent type's template.

**D8 Asset content.** All prose lives in `assets/prompts`; code holds none.

- `git mv` `codex/draft-entry.md` and `apple-foundation-models/draft-entry.md` to `generate-candidate.md`, then rewrite: output is the schema-1 object only; locale is `{{locale}}`; the facts are the packet's `snippet-N` bodies, with `civil_date` and `target_date` used for adjacent-day wording; no `reviewed_memory`, `reflection_ranges`, `prior_draft` or `language`; the five style wordings (`standard`, `concise`, `reflective`, `chronological`, `thematic`) are headed by their identifiers and the model applies the one named in `style`; every `claim_support` entry cites `snippet-N` IDs; unsupported facts are never invented. Keep the Codex pins from Q3.
- New `chat.md` for both types: a reply in `{{locale}}` grounded in the supplied document and transcript, no document context means none is claimed, diary text is untrusted quoted data.
- Apple `session-instructions.md` keeps its safety text but stops dictating "return only the guided structure"; each task asset states its own output contract (guided generation object or plain-text reply).
- `git mv` the six legacy files to `docs/archive/prompts/<type>/`, add a short `docs/archive/prompts/README.md` (`Status: Archived`), exclude it from the asset registry, and rewrite the README inventory.

**D9 Fixtures.** Shared accept/reject fixtures live in `src-tauri/crates/diary-infrastructure/tests/fixtures/agent/generation/`. A file named `ok-*.json` must validate; `bad-<code>-*.json` must fail with that code. The test fails on any file with another prefix, so a fixture cannot be added unpinned. Oversized cases (1 MiB draft, 8 MiB result, 2,001 support entries) are built in test code, not stored. P1-M17–P1-M20 reuse these files in their adapter conformance tests. No JSON-Schema crate cross-checks them.

## Sequencing and tests

1. **Application contracts** (D1–D3, D5, D6): types, limits, `Locale`, packet constructors, `Run`, capability, fake runner. Tests: `profile_status_has_the_eight_states`, `agent_kind_maps_every_config_profile` (infrastructure, uses config `Profile`), `request_rejects_empty_selection`, `request_enforces_message_and_transcript_bounds`, `locale_parse_accepts_bcp47_shapes_and_rejects_braces_spaces`, `error_codes_are_the_closed_allowlist`, `error_display_carries_no_content`, `late_result_after_committed_cancel_is_rejected`, `late_delta_is_ignored`, `success_cannot_race_cancel`.
2. **Assets** (D8): `git mv` and rewrite; update the README inventory. Run `git grep` for the four old names and the removed field names; fix every link.
3. **Loader** (D7, D6): embedded table, parse/validate/render, capability from assets. Tests: `front_matter_is_parsed`, `provider_must_match_directory`, `apple_requires_default_and_not_applicable`, `cli_model_and_effort_pass_through_unchanged`, `unknown_placeholder_is_malformed`, `required_placeholders_must_appear_once`, `diary_text_with_placeholders_is_not_expanded`, `missing_asset_names_the_action`, `malformed_asset_disables_only_its_action`, `no_fallback_to_another_agent_type`, `capabilities_follow_assets_and_adapter`, `embedded_table_equals_disk_and_registers_every_file` (ignores `README.md`), `generate_asset_matches_schema_and_packet`, `generate_asset_names_all_five_styles`, `chat_asset_matches_packet`.
4. **Output validation and packets** (D3, D4, D9): validator, encoder, fixtures. Tests: `generation_fixtures_match_their_names`, the in-code size cases, `encoded_packet_over_256kib_is_context`.
5. **Docs and review**: update the files above; run `scripts/gate.sh` once; fill the evidence record.

The loader tests that parse real assets run against the shipped files, so they also pin the rewrite from step 2.

## Review focus

- The new Apple and Codex prose is reviewed by reading, since no model runs; a test can pin field names and placeholders but not quality.
- Confirm `AgentError` has no free-text field and that nothing logs a rendered prompt.
- Confirm the application crate gained no dependency and the diff touches none of the excluded crates.
- Check that rejecting an empty draft (D4) and the 1 MiB chat-reply bound (D1) are accepted as engineering bounds, not product changes.

## Risks and limits

- **No live evidence.** Nothing here runs a model, a CLI or the native framework. Schema/prompt compatibility is checked structurally (field names and placeholders). Whether any model produces schema-1 output is proven per adapter in P1-M17–P1-M20.
- **Unverified Codex pins.** `gpt-5.6-luna`/`medium` stay in the tree by owner choice. The loader accepting them proves nothing about availability or protocol support; the Codex adapter must verify them before sending and otherwise send nothing.
- **Embedding proof.** The embedded-table test proves the library carries the current files and reads no path. It does not prove the release `diary-server` binary contains them, because no consumer links the loader yet. The first consumer (P1-M17) records that check.
- **Locale check is structural**, not a registry lookup.
- **Chat reply bound** reuses the 1 MiB limit without an architecture source.
