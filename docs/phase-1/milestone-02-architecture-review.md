# P1-M2: Architecture review

Status: Active

This P1-M2 record captures the owner's architecture review, documentation fixes and follow-up interview. It separates design corrections from required implementation evidence; P1-M3 consumes the completed design for scaffolding only, and no runtime capability is certified.

## Scope and conclusion

Reviewed the [architecture overview](../architecture.md), all maintained contracts, D01–D17 and later owner clarifications, canonical product/UX behavior, prompt inventory and implementation handoff. The inward dependency rule, independently launched processes and Markdown/SQLite authority model remain appropriate to the approved scope. The main defects were incomplete recovery identities and retry ordering, ambiguous remote-write recovery, and unbounded or conflicting auxiliary-state contracts.

Existing uncommitted documentation/assets were preserved. No dependency, build-tool, application-code, source-data or service changes are part of this review.

## Primary-reference checks

Checked 2026-11-05. These checks support contract choices, not packaged or live-service acceptance:

- [Tauri capabilities](https://v2.tauri.app/security/capabilities/): application commands need `AppManifest::commands` for explicit restrictions; capability grants merge, and explicit configuration limits the enabled capability files.
- [Notion append](https://developers.notion.com/reference/patch-block-children): positional insertion and the no-move limitation support the checkpointed daily-anchor design; current documentation uses `position` and targets API `2026-03-11`.
- [Notion limits and retry guidance](https://developers.notion.com/reference/request-limits): documented throttling and committed-object identifiers support typed reconciliation; treating a temporarily absent read as proof of non-commit is unsafe engineering inference.
- [Cargo workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html): `default-members` determines root-command package selection; the scaffold must explicitly cover both binaries and inward crates under the prescribed gate paths.
- [W3C status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), [Apple progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators) and [React external-store snapshots](https://react.dev/reference/react/useSyncExternalStore): support focus-preserving announcements, honest indeterminate feedback and stable subscriptions. Timing/render budgets are engineering targets, not measured results.
