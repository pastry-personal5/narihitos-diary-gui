# P1-M20: Agent abstraction, diagnostics and Apple Foundation Models adapter work plan

Status: Active

This plan makes the four agents share one engine, one registry and one diagnostic vocabulary, then adds the Apple adapter. Scope and checklist are in the [overview](milestone-20-apple-foundation-models-adapter-overview.md); the contracts are the [Apple adapter](../architecture/editing-and-agents.md#apple-foundation-models-adapter), [trust and process lifecycle](../architecture/editing-and-agents.md#trust-and-process-lifecycle), [required evidence](../architecture/editing-and-agents.md#required-evidence), the [logging contract](../architecture/logging.md) and handoff E5/E11. It follows the [M19 work plan](milestone-19-qwen-code-adapter-architecture.md) and repeats none of it.

Read from the architecture, the M16–M19 code, the logging model and this Mac (macOS 26.7.1 arm64, SDK 27.2, `swiftc` at `/usr/bin/swiftc`) on 2026-11-06. No inference was run.

## Owner decisions

Interview and direction 2026-11-06, recorded in the [changelog](changelog.md) and [AGENTS.md](../../AGENTS.md).

- **Q1 — Bridge. Decided: a Swift helper process.** Launched under the shared `Host`. No FFI, no swift-bridge-style crate, no Cargo dependency.
- **Q2 — Build. Decided: `build.rs` compiles it with `swiftc`; if `swiftc` or the SDK is missing the build succeeds and the Apple profile is `unavailable` with reason `helper_missing`.** Approves `swiftc` from a Cargo build step; adds no dependency.
- **Q3 — Reasons. Decided: detailed reasons such as "Apple Intelligence disabled".** Every profile check reports a closed reason, shown as distinct text in Settings.
- **Q4 — Scope. Decided: make the four agents' abstractions correct in the codebase, and log every failure, blocked or locked state in detail.** Authorizes the stage-A refactor of the Codex, Claude and Qwen adapters (with no behavior change, under the existing suites) and the stage-B extension of the typed diagnostic model. "Detailed" is bounded by the logging contract: closed tags and counts, never text.

- **Q5 — Size. Decided: one P1-M20 with three gated stages.** No renumbering; P1-M21–P1-M28 keep their IDs.
- **Q6 — Order. Decided: the Apple spike first**, then stage A, B and C.
- **Q7 — Apple Intelligence. Decided: if the spike finds it unavailable, stop and tell the owner** with the exact reason. The owner enables it and says so; C18 stays unchecked until then and everything else proceeds on the fake helper.
- **Q8 — Drift. Decided: stage A preserves each adapter exactly.** Differences found between adapters (home checks, reachable statuses and similar) are listed in the evidence record as follow-ups for the owner, not changed.

## Open owner items

- **O1 — Live re-run spend.** After the refactor the three CLI live tests are re-run once to prove no behavior change (about 3 real turns each on the installed CLIs and the local endpoint). It spends account usage; it proceeds under the earlier live-test authorizations unless the owner objects.
- **O2 — Port change.** `check` returns `ProfileCheck { status, reason }`, so test call sites change from `check(..)` to `check(..).status`. Expectation values stay the same. Proceeds unless the owner objects.
- **O3 — Meaning of "locked". Resolved 2026-11-06:** the list below is what is logged: host busy (single-run gate), shutting down, lease ended, run directory unavailable, native session busy, model not ready and Apple Intelligence disabled. Any further state is one more closed reason value.

## Design decisions

**D1 Engine and protocol.** `agent/engine.rs` holds `Adapter<P: Protocol>` implementing `AgentRunner` once: gate, lookup, assets, packet, resolve, run directory, phases, preflight, supervised spawn, common stop/escape/exit mapping, validation, `Run` finish, active counter and logging. A `Protocol` supplies only:

```rust
pub trait Protocol: Send + Sync + 'static {
    fn kind(&self) -> AgentKind;
    fn launch(&self, host: &Host, entry: &Entry) -> Result<Launch, Reason>;   // exe + optional home
    fn env(&self, host: &Host, launch: &Launch, tmp: &Path) -> Vec<(OsString, OsString)>;
    fn preflight(&self, ctx: &Ctx, launch: &Launch, cancel: &CancelToken) -> Result<(), Reason>; // version or availability, never inference
    fn check_prompt(&self, prompt: &Prompt) -> Result<(), Reason>;           // e.g. Codex quoting rule
    fn invocation(&self, ctx: &Ctx, prompt: &Prompt, mode: Kind, rendered: String) -> Result<Invocation, Reason>;
    fn stream(&self, mode: Kind) -> Box<dyn Stream>;
}
pub trait Stream: Send {
    fn record(&mut self, rec: &[u8], run: &Run, sink: &mut dyn EventSink);
    fn conclude(&mut self, outcome: &Outcome, inv: &Invocation, prompt: &Prompt) -> Result<Collected, AgentError>;
}
```

`Collected { bytes, structured }` is all the engine needs to validate. The exact signatures are fixed when Codex is ported first, and are changed only if a protocol cannot express its behavior without engine edits. A protocol never touches the supervisor, the run directory lifetime, the active counter or logging.

**D2 Host.** `Host::new(..)` is called by the server wiring and by `tests/support` (a shared test kit that replaces the `codex.host()` pattern). Adapters hold `Arc<Host>` only. Lease end and shutdown call the one host, as now.

**D3 Registry.** `agent/registry.rs`: `Agents` holds one `Adapter<P>` per registered kind and implements `AgentRunner` by dispatching on `profile.kind`; an unregistered kind is `unavailable`. It exposes `registered(kind)`. `ProfileService::new(table, Arc<Agents>)`; P1-M21/P1-M22 take `Arc<dyn AgentRunner>`. Registration happens in one function in the infrastructure crate, with a test over `AgentKind::ALL`.

**D4 Kind table.** `KindSpec { kind, asset_dir, default_binary: Option<&str>, needs_home, assets: &[&str], pins: PinPolicy }`, one entry per kind. `AgentKind::asset_dir` and the Apple branches in `assets.rs` read it. Config types stay in `config` (the `Profile` enum and its exhaustive-mapping test remain).

**D5 Check result and reasons.** `ProfileCheck { status: ProfileStatus, reason: Option<Reason> }`. `Reason` is one closed, shared enum with `ALL` and stable snake_case ids, used by `check`, by refusals and by logs:

| Group     | Values                                                                                                                                                                                                                                            |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Profile   | `executable_missing`, `profile_home_missing`, `profile_home_not_directory`, `profile_unknown`, `kind_mismatch`                                                                                                                                    |
| Version   | `version_unsupported`, `version_unreadable`, `probe_timed_out`, `probe_failed`, `spawn_failed`                                                                                                                                                    |
| Gate      | `host_busy`, `host_shutting_down`, `lease_ended`, `cancelled_before_start`, `run_dir_unavailable`                                                                                                                                                 |
| Assets    | `assets_missing`, `assets_invalid`, `prompt_pin_rejected`, `packet_too_large`                                                                                                                                                                     |
| Apple     | `os_unsupported`, `device_ineligible`, `apple_intelligence_disabled`, `model_not_ready`, `model_unavailable_unknown`, `locale_unsupported`, `native_session_busy`, `native_error_unmapped`, `helper_missing`, `helper_untrusted`, `helper_failed` |
| Run (log) | `record_too_large`, `output_too_large`, `escaped_descendants`, `exit_nonzero`, `result_missing`, `init_mismatch`                                                                                                                                  |

Status follows reason by one table in the engine (for example `executable_missing` → `Missing`, `version_unsupported` → `UnsupportedVersion`, `host_busy` → `Busy`, probe and spawn faults → `Failed`, the rest → `Unavailable`). Only profile, version, gate, asset and Apple reasons reach the API; run reasons are log-only. Settings text exists for every API-visible reason and an exhaustiveness test ties the TypeScript map to the Rust list.

**D6 Conformance suite.** `tests/agent_conformance.rs` iterates `AgentKind::ALL` with a per-kind fake (the existing `examples/fake_cli.rs` modes plus an `apple` mode) and runs one shared matrix. The M17–M19 suites stay as they are.

**D7 Typed diagnostics.** New `EventCode`s: `agent.check`, `agent.blocked`, `agent.helper` (extraction, hash check, launch), and the existing `agent.run` enriched. New tag enums in `diary-application::diagnostics`: `AgentTag` (kind), `ActionTag`, `PhaseTag` (last phase reached), `CodeTag` (all 11 `AgentErrorCode`), `StopTag`, `ExitTag` (success, code, signal) and `ReasonTag` mirroring `Reason`. Counts: elapsed ms (existing `count`), escaped, events, input bytes, output bytes, exit number. Levels: refusals and cancellations `info`/`warn`, failures `warn`, unmapped native errors, hash mismatch and escaped descendants `error`. The codec appends the agent keys after the current ones, omitted when absent; the parser stays strict; `trace` re-renders them and `recent:` includes agent warnings and errors.

**D8 What is logged, and what never is.** The engine emits:

- `agent.check`: kind, status, reason, elapsed, and whether the reason changed from the previous check of that alias.
- `agent.blocked`: every refusal before a process starts, with its reason and the phase reached (including busy, shutdown, lease end, stale profile after reload, assets, pin, packet, run directory, executable, home, preflight failure).
- `agent.run`: kind, action, last phase, code, reason, stop cause, exit class and number, escaped count, event count, input and output byte counts, elapsed.
- `agent.helper`: extraction, hash mismatch, launch failure and unmapped native error.

Child stderr and helper errors are classified in code (patterns already used by `classify`, the Apple helper's closed error codes) and only the class is logged. Prompts, replies, diary text, native messages, paths, executable names and environment values never reach a record, and a record that cannot be built from tags is dropped, as the contract says.

**D9 Helper protocol.** `apple-fm`, one Swift file, no package, deployment target `macos26.0`. Argv holds only the command. `availability` prints one JSON line (state, closed reason, OS, context size, supported languages) and creates no session. `run` reads one JSON request from stdin (instructions, prompt, locale, mode) and writes JSON lines: `delta`, then one terminal `result` or `error` with a closed code. The terminal line decides the outcome; exit codes are advisory. `supportsLocale` is checked before inference so `locale_unsupported` costs nothing. Foundation Models is linked weakly so an older OS yields `os_unsupported` rather than a dyld failure.

**D10 Sessions and output.** A fresh `LanguageModelSession` per run with the Apple `session-instructions` asset; generation uses guided output (`@Generable` type or a runtime schema, decided by the spike) mirroring schema 1; chat uses plain text. No tools, no file access, model and effort never sent. A Rust test compares the Swift output type's field list with `GENERATION_SCHEMA`.

**D11 Embedding.** `build.rs` runs `swiftc` with `cargo:rerun-if-changed`, writes the binary to `OUT_DIR`, and emits a cfg flag; without the toolchain it writes an empty file and `helper_missing` is the result. The Rust side `include_bytes!`s it, extracts once per process to `<runtime_root>/native/apple-fm-<hash>` (0700), re-hashes before each launch and refuses on mismatch (`helper_untrusted`).

**D12 Fixtures and live test.** Real captures under `tests/fixtures/agent/apple-<OS>-<SDK>/`, redacted; the suite is `agent_apple.rs` plus `profiles_apple.rs`. `apple_live.rs` is `#[ignore]` and gated by `DIARY_APPLE_LIVE=1`, split into `live_availability`, `live_generation`, `live_chat`, `live_cancel`; it records OS, SDK, timing, context size, supported languages and that no run directory or escaped process remains. The spike also records whether availability or inference behaves differently while the screen is locked or the Mac is asleep; this is evidence only, with no claim beyond what is observed.

## Sequencing and tests

Each numbered step ends with its affected tests green; stages end with the full gate.

1. **Owner decisions** Q1–Q4 (done 2026-11-06).
2. **Apple spike (throwaway, this Mac).** Print availability, run one chat and one guided request, trigger real errors (context, locale), check the OS 26 versus OS 27 error families and the locked-screen behavior. Decide `@Generable` against a runtime schema. If Apple Intelligence is unavailable here, record the exact reason and continue at fake-helper level; C18 then stays unchecked.
3. **Stage A.** (a) Standalone `Host`, test kit, `Agents` registry and `ProfileCheck` plumbing with Codex, Claude and Qwen unchanged otherwise. (b) Extract the engine from Codex; run `agent_codex`, `agent_process`, `agent_generation`, `profiles_*`. (c) Port Claude; run its suite. (d) Port Qwen; run its suite. (e) `KindSpec` table. (f) Conformance suite over the three CLI kinds. (g) Stage-A gate, `scripts/smoke/agent.py`, one live re-run of each CLI (O1). **Stop and report** if any step needs an edited expectation beyond constructors and `.status`.
4. **Stage B.** Tag enums and event codes; codec, parser, trace and docs; engine emission points; table-driven completeness test; seeded-string scan; trace fixtures; stage-B gate.
5. **Stage C.** (a) Helper, `build.rs`, embedding, trust check (C11). (b) Apple protocol and fake `apple` mode (C12–C15). (c) API, bridge, TypeScript and Settings reasons for all four kinds (C16). (d) Assets and capability (C17). (e) Conformance suite extended to Apple. (f) Fixtures, live test, smoke (C18). (g) Docs (C20), stage-C gate, evidence record.

If the spike or the live test cannot run, leave C18 unchecked and report the blocker rather than shipping an error mapping from memory.

## Review focus

- Stage A changes no observable behavior: argv, env, pins, fixtures, error codes and phase order stay identical for Codex, Claude and Qwen.
- No protocol reaches around the engine to the supervisor, run directory, counter or logger.
- The reason set is closed and exhaustive: adding a variant fails the status table, the log tag mapping, the TypeScript map and the completeness test.
- No record, error or fixture carries content, native text, paths or executable names.
- The helper registers no tools, opens no files and contains no `PrivateCloudCompute`; stdin is its only input.
- Availability is checked in `check` and again before each run; there is no fallback to another provider.
- The embedded helper is hash-checked before every launch.

## Risks and limits

- **Large refactor.** About 1,300 lines of working adapter code move. The mitigation is order (one adapter at a time), the unedited suites, the fixtures, the smoke and one live re-run; a failure that needs an expectation edit stops the work.
- **Abstraction fit.** Four protocols are enough to find the seams but not to prove a fifth fits; the conformance suite and the registry test are the guard.
- **Wider logging surface.** New codec keys touch a strict, versioned format and the trace tool; old lines must keep parsing and the scan must stay clean.
- **Packaged interop is only proven on this Mac.** The helper runs on this OS and SDK; other macOS versions are unproven (the contract's acceptance target). OS 27 error cases cannot be exercised here.
- **Soft-skipped build.** A machine without the toolchain builds an app whose Apple profile is permanently `unavailable (helper_missing)`; the gate passes there but the Apple evidence cannot be produced.
- **The system model changes with the OS.** Acceptance records OS, SDK and model metadata and makes no model-version or quality claim.
- **Small context.** Oversized input surfaces as `context`; reduced-selection handling is P1-M22.
- **Helper protocol is internal.** It is not versioned for outside use and may change with the SDK.
- **Read-only status is not enablement.** No route starts a run until P1-M21/P1-M22; `agents_available` stays `false`.
