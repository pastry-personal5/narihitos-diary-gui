# P1-M19: Qwen Code adapter work plan

Status: Done 2026-11-06

This plan adds the Qwen Code adapter behind the P1-M16 `AgentRunner` port on top of the P1-M17 supervisor, the P1-M18 shared `Host` and the profile status service. Scope and checklist are in the [overview](milestone-19-qwen-code-adapter-overview.md); the contracts are [agent port and profiles](../architecture/editing-and-agents.md#agent-port-and-profiles), [trust and process lifecycle](../architecture/editing-and-agents.md#trust-and-process-lifecycle), [required evidence](../architecture/editing-and-agents.md#required-evidence) and handoff E5. It follows the [M18 work plan](milestone-18-claude-code-adapter-architecture.md) and repeats none of it.

## Findings that shaped the plan

Only non-inference commands were run, and `settings.json` was inspected for key names and types only (no values). The planning interview was refined by an evidence review the same day; F2 and F3 corrected statements made during the interview.

## Owner decisions

Interview 2026-11-06, recorded in the [changelog](changelog.md) and [AGENTS.md](../../AGENTS.md).

- **Q1 — Status. Decided: `ready` after the version check.** No auth probe exists. This overrides the contract's `available_auth_unknown` option for Qwen; the architecture text is edited to say `ready` means installed and supported only.
- **Q2 — Versions. Decided: the `0.26.x` family.** Fixtures come from the single patch the capture reports (0.26.4 at planning); other 0.26 patches are accepted but unproven, and the live test re-proves the installed version.
- **Q3 — Pins. Decided: model only, `qwen3.6:35b-a3b`.** Sent as `--model qwen3.6:35b-a3b` from the asset. Effort is settings-only (F3) and stays unpinned. If the live test rejects the model, report and ask; never fall back silently.
- **Q4 — Live test. Decided: agent-run, no turn cap, no human gate**, on the default `~/.qwen` profile home and its local endpoint. Wall time is bounded by the run deadline. If the endpoint is down, C09 stays unchecked and the blocker is reported.
- **Q5 — Isolation. Decided: `--bare`, tools off, recording off, private cwd; amended 2026-11-06 to `--safe-mode`.** The spike showed `--bare` drops the endpoint (F2); the owner told the agent to try the options and use best effort, and `--safe-mode` works.
- **Q6 — Home. Decided: always set `QWEN_HOME=<profile_home>`.** If the spike shows the endpoint needs it unset for `~/.qwen`, omit it for that path as Claude does, and record the reason.

## Design decisions

Per the owner decisions above.

**D1 Shared host.** No host change is planned. `QwenAdapter` holds `Arc<Host>` like Claude and reuses `RunDir`, `Active`, `StopFlag`, `env`, `resolve`, `probe`, `log_run`, `classify`, `GENERATION_SCHEMA` and `cancel_all`/`shutdown`. If Qwen needs something the host lacks, extend it with M17/M18 suites unedited as the regression net.

**D2 Qwen `check`.** Resolve the executable (override, else `qwen` on the launch `PATH`). Missing or non-directory `profile_home` → `unavailable`. `--version` output must match `0.26.<n>`, else `unsupported_version` (`failed` on error, timeout or unparsable). Success → `ready`. 5 s through the supervisor with `QWEN_HOME` set, small output bound, `busy` while a run exists. No model turn; `settings.json`, credentials and memories are never read or copied by the app.

**D3 Environment.** `Host::env` allowlist plus `QWEN_HOME=<profile_home>` and `QWEN_TELEMETRY_ENABLED=0`. Nothing else, and never a credential, `OPENAI_*`, `QWEN_*` or proxy variable inherited from the server. The child's cwd is the private run directory.

**D4 Qwen `run`.** Fixed argv built in one function and finalised from the capture spike:

`--safe-mode --output-format stream-json [--include-partial-messages] --max-tool-calls 0 --max-session-turns 4 --max-wall-time 540s --chat-recording=false [--json-schema <GENERATION_SCHEMA>] --model qwen3.6:35b-a3b` (the spike ran this shape with `--max-wall-time 120s`; the final value is set below the host's 10-minute deadline)

- The rendered prompt goes on stdin; no diary or chat text appears in argv (F4). Model comes from the asset unchanged, and the `system.init` record must report that model and a `0.26.x` version before any result is accepted (F15).
- Generation passes the same closed schema-1 object as Codex and Claude (`GENERATION_SCHEMA`) and takes the result from the terminal result event; chat omits `--json-schema` and takes the plain result as a `Reply`. Chat passes `--include-partial-messages` only if the fixtures show usable deltas within the M16 bounds; generation does not.
- Events map to `AgentEvent::Phase`/`Delta` through `Run::accept`. Unknown kinds are ignored and counted; a non-JSON record is `invalid_output`; a missing terminal result, an error result, exit 55 or `escaped > 0` is `failed`/`invalid_output`. Only validator-approved output becomes a `Candidate`.
- Error mapping uses `classify` plus Qwen patterns recorded with the fixtures: connection refused, endpoint unreachable, 401/403 and unknown-model patterns map to `unavailable`; unobserved patterns are marked synthetic as in M17/M18.

**D5 Logging.** Same content-free `agent_run` record as Codex and Claude.

**D6 Assets.** `assets/prompts/qwen/{generate-candidate,chat}.md` with `provider: qwen`, `model: qwen3.6:35b-a3b`, `reasoning_effort: not-applicable`; the Claude body reused with only provider wording changes. The loader and embedded-table tests add `qwen`; the README inventory row changes from "None yet".

**D7 Status API.** `ProfileView` marks Qwen registered, `check` dispatches to `QwenAdapter`, `ProfileService::new` gains the adapter argument, and `diary-server` wires lease end to the shared host once. Apple stays `adapter_unimplemented`/`assets_missing`. No route, bridge command or Settings change beyond test coverage and any new status text.

**D8 Fake CLI and fixtures.** Extend `examples/fake_cli.rs` with a `qwen` mode (success, split records, malformed final, version drift, endpoint down, rate limit, context, exit 55, flood, hang, TERM-ignoring, late output) and add a `qwen` fake to `scripts/smoke/agent.py`. Real fixtures go under `tests/fixtures/agent/qwen-<captured version>/`, redacted (F14).

**D9 Live test.** `tests/qwen_live.rs`, `#[ignore]` and gated by `DIARY_QWEN_LIVE=1` plus `DIARY_QWEN_LIVE_HOME=<profile_home>`; split into `live_check_and_generation`, `live_chat`, `live_cancel`; records version before and after, elapsed time, whether the model pin and flags were accepted, that no run directory or escaped process remains, and any unexpected profile-home writes.

## Review focus

- No host or Codex/Claude behavior change; M17/M18 suites pass without edited expectations.
- No key, `settings.json` content, endpoint URL, prompt, response, path or stderr appears in any log, `AgentError` or fixture.
- The API key never reaches argv; `--openai-api-key` is not used under any option.
- The child cannot load project context files or memories (`--safe-mode`, private cwd) and cannot call tools (`--max-tool-calls 0`).
- `ready` is documented everywhere as "installed and supported", never "logged in".
- Version drift: fixtures, path and allowlist agree on the captured version.

## Risks and limits

- **`ready` is unverified readiness.** A stopped local endpoint, a missing model or a bad key still shows `ready` until a run fails; the failure maps to `unavailable` at that point (Q1).
- **`--safe-mode` is hygiene, not confinement.** It does not stop the CLI from reading `settings.json`, which is needed for the endpoint, and it leaves the model's tool set registered; `--max-tool-calls 0` is what stops tool use.
- **No effort control through the CLI** (F3): output quality follows the profile's own `model.reasoningEffort`.
- **Pre-1.0 protocol.** A newer 0.26 patch is accepted but unproven; a 0.27 or later CLI is `unsupported_version` until fixtures are added. Qwen may self-update (F8).
- **Profile home writes** (F9) include usage records and sessions beside the owner's memories when the default `~/.qwen` is used.
- **The model pin is advisory.** An unknown model silently falls back to the configured one (F15); the init-record check is the only guard.
- **Local model latency.** A 35B local model can be slow or cold; the run deadline bounds it and the live test records timing rather than asserting it.
- **Isolation flags are hygiene, not confinement.** The owner trusts the installed CLI; retention and terms of the endpoint are unverified.
- **Read-only status is not enablement.** No route starts a run until P1-M21/P1-M22; `agents_available` stays `false`.
