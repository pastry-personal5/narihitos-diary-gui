## Design and affected modules

1. **Capability and ownership.** Extend diary-application source types/ports and infrastructure source adapters with an independently gated trash_pair policy. Reuse Narihito producer validation where applicable, but do not infer delete eligibility from write eligibility. Return bounded member descriptors with relative labels and status only. Resolve roots and fresh files under coordination; inspect potential shared references across the configured source namespace with bounded scanning. Any limit, unreadable potentially referencing source or unsupported ambiguity blocks ownership proof. Revalidate ownership at confirmation and before each move; no wildcard assets or arbitrary body-link following. Stream audio hashing in 64 KiB chunks with the pinned CatalogAudioInspector maximum of 64 MiB and a cancellable 120-second preparation deadline. Reuse scan ceilings of 100,000 entries and 10,000 candidates across the complete ownership assessment, not once per page/date. Exceeding a limit disables mutation rather than skipping validation. Validate a present audio_sha256 against the full observed audio digest. Audio decoding is producer-harness evidence, not permission to follow arbitrary references. Start the token lifetime only after preparation completes; do not count hashing time against the confirmation window.
2. **Preview.** Application service generates an opaque random token with a monotonic 60-second lifetime and stores a bounded session-owned plan. Bind source identity, config generation, native root identity, full member observations and preview type (initial or continuation). Keep tokens transient; restart requires a new preview. Missing expected audio remains a plan member with a missing outcome and is rechecked before admission; newly appeared audio changes the plan. No SQLite transaction remains open during reads or user confirmation.
3. **Persistence.** Add the next numbered sqlite migration for trash_members and necessary durable plan/receipt data. Store original root/path/member identity, digest, ordinal, status and opaque native receipt privately, with bounds and schema validation. An application transaction admits the operation, first step, consumed authorization and sorted reservations together. Token state and durable admission must share a serialized admission boundary: failure rolls back consumption; successful admission cannot replay side effects. Persist only a nonreversible token fingerprint with a unique constraint, the bound plan hash and admitting operation/step; never persist the bearer token. Keep transient token locking through commit. A crash after commit but before transient consumption is harmless: the fingerprint cannot authorize a second operation. A duplicate request is authenticated against the current workspace/session, then matched by stable operation/step business inputs without requiring the old session or token to survive. Hash normalized business inputs excluding token/session bytes. Existing operation/step lookup precedes expiry checks after authentication. Use ledger paused internally for public needs_confirmation.
4. **Native execution and recovery.** Add a Trash adapter and deletion-specific coordination in infrastructure. Commit member intent before each native call, perform Markdown first, then validated audio, commit result before advancing. Never fall back to unlink or manual moves into ~/.Trash. Revalidate root, path and resource identity inside the accessor. Persist native returned location and identity without exposing Trash paths. Startup reconciles each in-flight member; a lost receipt with no provable provenance is uncertain, with no automatic repeat. Local source absence alone is insufficient. Cooperating coordination does not promise atomic CAS against arbitrary uncoordinated writers.
5. **Continuation and lookup.** Keep the original plan and operation ID. A continuation preview carries expected_checkpoint; confirmation adds a fresh step_id and token and targets only failed unchanged members, plus originally pending audio after a retried Markdown move succeeds. Recheck retained audio ownership even if the Markdown has moved, using the durable original plan plus a fresh shared-reference assessment. A replacement Markdown never becomes a continuation member; block continuation if it now claims the audio. Paused/uncertain reservations remain until safe completion or existing explicit recovery rules resolve them. No new force-clear or restoration behavior is introduced. Durable results must remain discoverable after restart without a live import/job handle; the discovery and state rules below are required work, not an existing capability claim.
6. **Transport.** Add diary-api source-trash routes and typed bridge commands preview_source_delete and confirm_source_delete, registered in build.rs, capabilities, invoke handler and architecture tests. Use the fixed trash-preview/trash routes with a tagged initial/continuation payload rather than a generic URL bridge. Include operation_id, step_id, expected_checkpoint and token for confirmations. Reuse get_operation for durable lookup; add missing typed member-result decoding there. Add the authenticated, paginated unfinished-deletion discovery route/command specified below. Preserve existing Authentic/source-save lookup decoding and its callers; map paused to needs_confirmation only in the tagged Trash representation. Bound payload/member/result sizes consistently with the ledger's existing result limits. Return allowlisted codes for expiry, stale/config/member change, unsupported, ownership ambiguity, cloud unavailable, busy, partial_trash and uncertainty; no native exception, body or absolute path reaches the WebView.
7. **Client.** Extend navigation contracts/model, tauri-bridge and Explorer with a dedicated Trash coordinator and accessible confirmation/results dialog. Resolve dirty source edits using existing Save/Discard/Cancel behavior before preview; wait for in-flight saves. Show exact snippet/audio relative labels and missing states, and allow cancellation before admission. After admission query the durable operation until a known outcome; lost replies reuse IDs. A fresh retry preview requires explicit confirmation. Remove moved-source selections and invalidate buffers in every cached date, while preserving immutable snapshots and unrelated text. Keep partial/uncertain operations reachable through the existing app feedback area after reconnect/status lookup; do not depend on the removed tree row to expose retry. Date change does not retarget admitted work; close preserves its recovery handle. Refresh/discover unfinished operations on every admitted session; keep active operation handles in the session coordinator while dialogs/tree rows unmount. A failed preparation or cancelled dialog retains source selections and text. After a moved result, disable stale snapshot rows and their source actions until re-import; never remove a source from an already saved Authentic or rewrite its text. If another buffer for the moved source acquired unsaved edits after admission, retain a detached read-only copy with an explanation instead of silently dropping those edits.

## Review fixes and implementation contracts

The 2026-11-06 review found the following gaps in the first plan. These are internal details under D17, not new product choices or evidence that Trash works.

### Durable discovery and transport

Current GET /operations/{id} requires a known ID; status is unauthenticated and does not enumerate operations. Bridge OperationState carries a generic result string, and ledger unfinished() is an internal, unpaginated query. None is a restart-discovery mechanism for a client that lost its memory.

Plan an authenticated GET /operations?kind=source_trash&state=unfinished route and typed list_source_deletions command with fixed parameters, a default page of 50 and maximum of 100, and opaque keyset cursors. Return only operation ID, checkpoint, public state, safe source label/ID and bounded member summaries, scoped to the connected workspace. Cursor validation binds the workspace and filter; the client deduplicates IDs and refreshes after paging because operations may finish during enumeration. No credentials or operation data enter public status. Register the minimum Tauri permission and add the route/command to the maintained API inventory during implementation. The existing single-ID lookup remains available for terminal results and lost-reply recovery. Client-only persistence is insufficient for unfinished-work discovery.

Use a discriminated Trash result containing original source ID, plan hash, checkpoint, public state and at most two ordinal members (Markdown and expected audio). Member results contain safe relative labels, moved/missing/failed/uncertain status, an allowlisted reason and retry eligibility; pending members while running are explicitly pending, never reported missing or failed. Private paths, identity evidence and native receipts stay in trash_members. Keep step outcomes within the existing 1,024-byte bound by recording compact admission/checkpoint references; materialize member summaries from the authoritative rows for polling. Keep the existing 4,096-byte operation-result bound; never truncate a path or receipt into an apparently valid identity.

Initial preview is source-ID based with a fresh observation. Continuation preview also carries operation_id and expected_checkpoint; continuation confirmation carries those plus a new step_id and token. Hash the source ID, action kind, immutable plan hash, eligible member ordinals and expected checkpoint. Persist these business fields so duplicate comparison after restart never depends on a transient preview. Reject an existing operation/step ID with changed business fields; a new step cannot masquerade as an initial admission. Existing-step responses describe that step's admitted checkpoint; current operation status is queried separately and cannot authorize another move.

### Member and operation transitions

| Observation / event                                                       | Required transition and allowed next action                                                                                                                                                 |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Expected audio absent in preview and still absent at admission            | Record missing without a native call; do not reinterpret unavailable, unreadable or changed files as absent. Reserve its canonical path as well.                                            |
| No intent committed for a member                                          | No native call was authorized; recovery still revalidates the original plan and requires fresh confirmation before new moves.                                                               |
| Intent committed, native move not durably receipted                       | Reconcile from proven native evidence. An unchanged original file alone does not distinguish a never-started call from a lost reply; otherwise mark uncertain and retain reservations.      |
| Definitive native failure with unchanged original and no completed effect | Record failed; pause as needs_confirmation. If Markdown failed, audio remains pending and cannot move ahead of it.                                                                          |
| Markdown later succeeds on a confirmed retry                              | Its originally planned pending audio may now run after fresh validation under the same step. This is the only pending-member continuation; previously moved/missing members stay completed. |
| Markdown moved, audio definitively failed                                 | Pause as needs_confirmation; a new step may retry only that unchanged original audio. Replacement Markdown/audio is never substituted.                                                      |
| Root/member/ownership changes after admission or during continuation      | Perform no further move; retain completed effects, pause with a readable blocker and retain reservations. A changed plan requires a new action; it cannot bypass the older reservation.     |
| Any unresolved member provenance                                          | Mark operation uncertain; status/reads remain available, and no confirmation token alone can release quarantine.                                                                            |
| Every planned member moved or confirmed missing                           | Atomically finish succeeded with honest per-member outcomes and release reservations. Native Trash completion makes no cloud-upload claim.                                                  |

Store pending/intended distinctions separately from user-facing final outcomes. Reconcile all incomplete Trash operations before advertising mutation readiness, using persisted workspace, canonical source root/native identity and adapter version, not just the current config generation or entries root. Root removal/repointing, capability changes and corrupt member rows must not reinterpret an old relative path or discard reservations. Add migration/reopen tests from an actual pre-Trash schema and authoritative corruption fixtures. No automatic inspection resolution, force release, restoration or permanent cleanup is introduced; an uncertain operation may remain blocked until provenance or explicit existing workspace repair establishes safety.

### Ownership, execution and evidence boundaries

The ownership assessment covers all configured source roots and dates that could claim the candidate audio, with no immutable import-page or selected-date shortcut. Keep the checks bounded and fail closed on incomplete observations. Test a reference added after preview and between member moves. Acquire the application resource coordinator before final confirmation validation, hold it across durable admission/execution, and repeat filesystem checks inside deletion coordination. No database transaction spans hashing, coordination waits, native calls or user interaction. Filesystem cooperation does not freeze every producer or uncoordinated writer; document this remaining race rather than claim a globally atomic ownership snapshot.

The existing ledger admit/advance calls cannot atomically add member rows and consume authorization by being called successively. Introduce focused transaction helpers (as finish_tx already does), keeping application ports and infrastructure SQL in their existing layers. Admission and continuation each commit their authorization, checkpoint, work plan changes and reservations in one transaction. Receipt and member progress are committed together; a database failure after a native move stops execution before another member is attempted.

The producer harness must compile and exercise the pinned catalog candidate/read/recovery path, not a reimplementation or codec-only surrogate. Record the submodule commit, compiled file list, commands, fixture results and limitations. Generate a valid small AAC/M4A fixture with installed Apple frameworks so catalog reopening actually reaches its audio checks; random bytes with an .m4a suffix do not establish producer compatibility. Assert structured outcomes for intact neighbors, full deletion with retained empty assets directory, missing audio, Markdown failure, Markdown moved/audio retained, retry completion, and replacement-path preservation. Catalog recovery rows or issues caused by retained directories must be recorded explicitly; neither suppress them in the harness nor expand into directory deletion.

Keep fault hooks in the existing fault-injection build, with separate artifacts; native calls use only freshly created harness fixtures. Distinguish simulated adapter failures from real NSFileManager receipts, and process termination from a returned error. Native loss-of-reply cases must prove honest uncertainty when receipt provenance is unavailable. Fixture cleanup may remove only test-owned temporary roots and verified test-owned Trash receipts, never empty Trash or touch personal entries. Do not run this destructive harness as part of plan review.
