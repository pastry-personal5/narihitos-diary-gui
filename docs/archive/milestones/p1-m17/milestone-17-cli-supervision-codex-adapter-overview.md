# P1-M17: CLI supervision and Codex adapter overview

Status: Done

Add bounded, process-group-supervised execution of one-shot CLI runs and the first real adapter, Codex, behind the P1-M16 `AgentRunner` port, plus read-only profile status through the API and Settings. Chat, Generate, job store and any run-starting route stay out (P1-M21/P1-M22). The [work plan](milestone-17-cli-supervision-codex-adapter-architecture.md) defines findings, decisions, design, files, sequencing and tests.

## Entry conditions

- P1-M16 (port, bounds, validator, embedded Codex assets, capability model) and P1-M8 (configuration reload) are Done. Follow [agent port and profiles](../architecture/editing-and-agents.md#agent-port-and-profiles), [trust and process lifecycle](../architecture/editing-and-agents.md#trust-and-process-lifecycle), [required evidence](../architecture/editing-and-agents.md#required-evidence) and handoff E5.
- The [owner decisions](milestone-17-cli-supervision-codex-adapter-architecture.md#owner-decisions) of 2026-11-06 are recorded: read-only profile status (routes, bridge commands, Settings), automated tests including an automated live Codex schema turn that is not a human exit gate, and a `codex-cli 0.167.0`-only allowlist. Q4 (process-table escape detection), Q5 (report and ask on rejected pins), Q6 (ignore user config) and Q7 (about 5 live turns on `xpp8`) are also decided.

## Scope

Included: a generic supervisor in `diary-infrastructure` (private working directory, controlled environment, no shell, new process group, concurrent bounded pipe draining, record and total-output bounds, 120 s inactivity and 10 min wall deadlines, TERM/KILL cancellation, reaping, escaped-descendant detection); the Codex adapter (`check` with `--version` and `login status`, `run` with a fixed argv, schema file, stdin prompt, NDJSON events, last-message file, error mapping, validation through the M16 validator, `Run` cancellation epoch); a fake CLI test helper; a capture of exact-version fixtures; an env-gated live test; profile status/capability listing at `GET /profiles` and `POST /profiles/{alias}/check`, bridge commands and a read-only Settings list; embedding proof in the server binary; affected docs.

Not included: chat or generation routes, the single-run `busy` gate and job store, packet assembly from imports, SSE job events, any Chat or Generate UI (P1-M21/P1-M22); Claude, Qwen and Apple adapters; changing `agents_available` (stays `false`); any new dependency; Codex `app-server`; confinement or retention guarantees.

Deviations from the plan:

- Tauri commands are `list_agents`/`check_agent`: the capability guard in `tests/architecture.test.js` rejects command names containing `file`, which `profiles` does. The HTTP routes keep the contract names.
- `GET /profiles` reports `unchecked` for a Codex profile before any check (the plan said `unavailable`; `unchecked` is not misleading). Non-Codex profiles report `unavailable`; their capability reason is `assets_missing` until their assets exist (M16 precedence), then `adapter_unimplemented`.
- `Candidate` stays publicly constructible: infrastructure must call a public constructor, so a validator-only one is not cheap.
- Added `From<CancelToken> for Run` in the application crate so adapters route the port's token through the same commit-once guard (F8).
- `DIARY_CODEX_CAPTURE` was not built; fixtures were captured by hand from real runs.

Known gaps from the post-implementation review: process-table scans walk every PID and could be narrowed to the group; `POST /profiles/{alias}/check` has no cap on concurrent probes; a Codex launcher needing `node` on `PATH` would fail under the minimal `PATH` (0.167.0 is a native binary).

Evidence limits: one installed Codex version and the owner's account; `login status` is trusted as the auth probe; escape detection is best effort and sees only descendants alive at a scan (every 300 ms); the server's own SIGKILL leaves cleanup unclaimed; the allowlisted `PATH` (executable directory plus system directories) was sufficient for Codex 0.167.0, a native binary.
