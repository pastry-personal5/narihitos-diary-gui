# P1-M11: Explorer and editor navigation work plan

Status: Done (archived)

Implementation sequence for the [overview and checklist](milestone-11-explorer-navigation-overview.md). Apply the maintained [architecture](../../../architecture.md), [source identity/freshness](../../../architecture/sources-and-dates.md) and [UX contracts](../../../ux-gui.md); this plan introduces no dependency or source mutation permission.

## Current baseline and gaps

`App.tsx` has fixed scaffold columns and four Explorer buttons. `useAuthentic.ts` owns only the selected date, destroys its session on date changes and stops catalog pagination after five pages; `AuthenticPane.tsx` represents Draft/Entry as labels. `authentic-editor.ts` resets history on programmatic loads. Preserve the tested save queue and IME rules while moving ownership above mounts.

P1-M10 implements `import_date`, `list_sources` and `resolve_source_time` in the Rust bridge, but not their TypeScript/UI integration. Immutable body-less snapshots survive restart; resolutions do not change existing pages. Source bodies remain library-only. Current DTOs lack source grouping labels, captured-zone local date fields and detailed timestamp validity reasons. Unsupported/conflicting scan outcomes currently retain only a relative key and reason, losing the observation required by `read_source`; the library reader alone does not make those rows openable. Do not infer these from relative filenames, browser timezone or opaque IDs.

### Calendar and grouping

Add a narrow typed `get_calendar` Tauri command translating to an authenticated, read-only `GET /calendar` endpoint. This is a planned additive API, not an existing local-client command: server-owned Today requires a server request. Put civil arithmetic in the domain/application and named-zone/clock access behind server ports. Accept an optional validated anchor date and a bounded action (`month`, previous/next month, previous/next day, previous/next week, or Today); return ISO dates, weekday/grid fields, adjacent months and server-system Today. Keep the existing `DiaryDate` range (0001–9999), return null for unavailable adjacent dates and clamp month movement to its last valid day. Reject overflowing navigation without wrapping. Obtain Today from the server system zone through the authenticated bridge, not the browser or elapsed milliseconds. Return explicit boundary/unavailable errors. A calendar date's actual import validates whether it exists in the captured zone; a skipped date gives `invalid_diary_date` without inventing instants or relabeling saved Authentic dates. Browsing a month does not select a date or import it. Use a labeled grid, roving focus, civil arrow movement and Enter selection; Today follows the same guarded selection path. Bootstrap the initial date from the server response after connection; while unavailable, show a loading/error state and retry rather than using the browser date. Refresh Today on explicit activation and window focus without changing the selected date automatically. Keep calendar focus, browsed month and committed working date distinct. A failed/skipped-date import leaves the requested civil date visible with its error; Authentic access for that date remains independent of source import success.

Listings need an opaque source-root group handle (never the canonical namespace or its path hash), configured display alias/type, included local date/offset in the import's captured zone and safe warning/authority-validity codes. Preserve instant/path ordering within groups. Alias changes affect labels, not source identity. Distinguish identical relative paths under different roots. Attribute failure/collision groups at scan time rather than guessing a root in React; if provenance was not retained in a legacy snapshot, explicitly require re-import for the enhanced view. Persist the captured display/local-time fields and the chosen authority/eligibility explicitly in a versioned, body-less snapshot; `dating` alone cannot distinguish a resolved conflict from an unresolved warning. Do not reconstruct a stored choice from today’s resolution table. Keep snapshots immutable, bounded and restart-readable; decode existing versions without rewriting rows. Existing snapshots remain readable through their supported listing contract; enhanced grouping/reads that lack required provenance return an explicit re-import requirement. Never recompute old local dates using the current zone/rules. Paginate every outcome category, with explicit Load more rather than a silent page cap; render bounded pages/disclosed groups without adding a virtualization library.

### Source read boundary

Extend scan/import storage to retain a collision-checked source identity, root group and complete observation for each adapter-approved viewable unsupported/identity-conflict outcome. These rows remain warning/failure rows and generation-ineligible. Expose an optional read descriptor (`source_id`, snapshot ID, digest and `read` capability/reason); never fabricate a token from a relative filename or perform an unobserved read. Unparseable, unavailable and path-collision rows without a safe observation remain non-openable. Round-trip these descriptors through the versioned snapshot codec within its existing 16 MiB encoded bound, atomically with completion. Old snapshots missing them require re-import for body viewing.

`read_source(source_id, snapshot_id)` looks up the exact identity/token in a completed snapshot and freshly reads only that configured source. Compare the complete observation, including config generation/native identity/digest, using P1-M9 guards. A mismatch returns `source_stale`; it cannot silently open new bytes under an old listing. Reuse two source-worker slots and existing byte/cancellation bounds. Read response contains resource identity, context/digest, body, redacted capability/warning codes and safe display metadata; raw front matter and native token remain in Rust. Unsupported formats expose a body only when the existing adapter explicitly permits it. Enforce the existing 8 MiB file/1 MiB editor-body and 10 MiB encoded response limits before allocation/publication; the API returns a dedicated body DTO rather than serializing `SourceView` (which includes raw metadata). Revalidate root identity and config generation across worker execution, including a reload admitted during the read. Map missing/denied/not-downloaded/changing/stale/limit outcomes distinctly without leaking native errors. Failures/collisions without a valid identity are warning rows, not guessed paths to read.

Source mutation capabilities remain false until their later evidence gates. Source views therefore start read-only with an explicit Save-unavailable reason. Implement dirty-source transition handling in the resource coordinator and exercise it with synthetic capability-enabled buffers; this prepares later writers without claiming that a real source can be saved in P1-M11. If producer capabilities later permit edits, the same guard must retain local text/base observation on refresh and offer only actions actually supported. Never offer a working Save backed by a placeholder.

### Import, selection and refresh ownership

Keep a bounded session-owned context cache for visited dates, independent of mounted Explorer panels (see resource budgets below). Opening a first page is automatic; subsequent pages require Load more. A newly selected date starts its captured-zone import; revisiting can show its retained context with an explicit Refresh action. Use `request_id` for admission retries, track `import_id` through job events/lookup and fetch pages only after success. Transport acknowledgement is not scan completion. Deduplicate/coalesce repeated Refresh; do not queue unbounded scans. Cancel superseded scans where safe and ignore late results by server instance/session/connection epoch/date/import ID regardless of cancellation outcome. Preserve one request ID for retries of an uncertain admission with the same payload; an explicit Refresh or changed config generation creates a new ID. Recover a lost event by job lookup with bounded, non-overlapping polling while connected; `resync_required` triggers authoritative job/state lookup rather than replay assumptions. Stop polling on terminal state, disconnect or disposal. Distinguish a succeeded scan with `incomplete: true` from an unfinished/failed job; only the former has a listable snapshot.

After terminal success, stage replacement pages independently of the old context. Load one page at a time through explicit Load more, merging observations and provisional inclusion as pages arrive; do not automatically fetch every page to publish the first results. Finalize absence-based reconciliation only when `next_cursor` is null and coverage is complete. Until then, retained choices for unseen rows are pending and cannot supply active generation input. Pages show explicit loading/partial state; do not infer absence from an unloaded page. Validate stable context provenance on every page and strictly advancing, bounded cursors; duplicate/non-advancing/mismatched pages fail visibly without replacing valid state. Retrying a failed page uses that same immutable context/cursor. Failed refresh retains the prior context visibly marked stale. The 10,000-candidate scan bound and `incomplete` remain visible even after all pages load.

Selection is session-owned by source ID plus observed digest, independent of open/focused editor. Preserve checked/unchecked choices for unchanged observations; new eligible identities start checked. Changed observations are shown unchecked and invalidated until the user explicitly includes the fresh eligible observation; never carry a checked old observation directly to new bytes. Missing entries from a complete replacement invalidate their prior selection; incomplete coverage cannot establish deletion. Eligibility comes from the server’s resolved classification and capability, not the mere presence of a warning: an included source with a stored valid authority or informational warning can remain eligible. Unresolved timestamps/undated, unsupported/identity-conflicting, unavailable and dirty sources are generation-ineligible. Generate still explains the pending agent integration.

Resolution displays both valid instants and their captured-zone interpretations plus invalid-authority reasons. Confirm header/filename explicitly, then create a new import for that date; do not edit old pages or source bytes. A stored choice followed by refresh failure is reported separately and can be refreshed again. Stale bytes/config require re-import; invalid filename/directory evidence explains the external correction. Resolution replies from an outgoing date never replace the current Explorer.

### Resource tabs, saves and transitions

Use keys `authentic:<date>` and `source:<source_id>`; reserve candidate ownership for the AI milestones without constructing fake candidates. Draft and Entry resolve to the same Authentic key. Each resource retains its CodeMirror `EditorState` (undo/selection), scroll, load epoch, base revision/observation and save coordinator outside React editor mounts. Each buffer port reads/writes its own retained state even while inactive; never close over the active EditorView. Apply request-epoch/resource checks before any asynchronous load or reload writes a buffer (checking after `AuthenticSession.open` resolves is too late because it already calls `setText`). Re-reading an identical acknowledged revision must preserve undo/selection. Only the active view mounts; switching restores state without `setText`/history reset. Real reload/discard explicitly resets the relevant state. Cap retained resources (initially 32 tabs and 32 MiB UTF-8 body text) and refuse additional opens with a visible close-tabs action when full; never silently evict dirty/in-flight buffers. History also needs bounded retention and explicit stress verification; CodeMirror history depth alone does not bound bytes. Account for retained history/documents, queued retry bodies, pending loads and cached listings under an explicit client session budget of 64 MiB. Reserve before reads/edits or reject with a visible limit error while preserving existing text. This is an accounted retained-payload budget, not a promise that WebView process RSS stays below 64 MiB; measure long-document/tab/history stress and record overhead separately. Bound the import context cache to 32 dates within that budget; release clean unreferenced page data with a visible re-import state, retaining referenced observations and selection. If protected state fills the budget, refuse new work instead of silently dropping it. Client cache release never deletes durable server snapshots or user files. The 32 MiB body budget is not a total-memory guarantee.

Retain `AuthenticSession` instances for open dates and route editor access/acknowledgements by resource key, not the active view. Autosave continues after tab switches. Finish or defer active IME composition before detaching an editor; switching, date changes and close must not save partial composition. Date transitions still flush/settle the outgoing Authentic and any admitted writes before committing the selected date; read/import failure remains separate from saving. Opening a source does not select its date or change inclusion. Entry navigation selects its saved date through the same guard and opens its Authentic resource. Draft presents the selected-date Authentic and an honest no-candidates state. Create Empty targets the selected date even while a source tab is active; Save status identifies the relevant resource.

One transition coordinator handles date changes, tab close, refresh replacement and app close, replacing duplicate close handlers. Serialize transitions and disable duplicate requests while a guard is pending. App close settles every retained Authentic session and creation/admitted operation, including inactive tabs; only then call `finish_close`. A failed guard retains the current date, editor and focus with Retry/Cancel and the applicable explicit discard/reconciliation action. Create Empty reserves and captures its date/resource before submission; late completion opens only that resource and never replaces a newer active tab automatically. Source dirty guards allow Cancel or explicit Discard and Save only when genuinely available; pending/failed/uncertain saves block departure until reconciled. Discard requires confirmation and reloads a fresh valid context rather than replacing a base token beneath local edits. Closing a clean source or switching tabs is independent of checkbox inclusion. Reconnect/config reload invalidates source actions and requests fresh imports while retaining local buffers; preserve Authentic unsaved text and reconcile revisions before resuming writes. On disconnect keep sessions and exact pending operation IDs/bodies alive, pause new writes, and mark uncertain outcomes. Reconnect first queries admitted operation results and current revisions; never resend uncertain saves with fresh IDs or create a new session over unsaved text. An SSE `authentic_changed` hint invalidates all retained Authentic sessions and refreshes the saved-date catalog, not just the active tab; dirty buffers reconcile without replacement. Ignore all stale resource loads/events. Window focus can validate clean views but cannot overwrite a dirty buffer.

### Layout, messages and accessibility

Use CSS grid and existing controls, with session-only pane sizes. Implement separators between Explorer/editor/AI Chat and above Global Messages using pointer capture and keyboard arrows, semantic orientation/value bounds and visible focus. Start Global Messages at about eight lines; clamp panes to keep editor content usable. At narrow window sizes use bounded overflow rather than silently hiding panes or focus. Settings returns focus to its invoker without destroying editor state.

Global Messages has time, severity text plus a non-SF fallback marker/color, a labeled polite log region, oldest-first order, and bottom pinning only while already at the bottom. Retain at most 500 messages; disclose that older session messages were removed. Jump to latest is explicit; notices never activate a tab. Use allowlisted user-facing errors without raw paths, bodies, tokens or stderr. Wire existing connection/save/import outcomes; leave AI/export messages to their implementations. Avoid duplicate announcements for repeated job snapshots.

## Packaged synthetic navigation smoke procedure

Use a disposable workspace and configured synthetic source roots only; record OS/build, fixture generator/commands, results and limitations in the overview. Do not run these steps against personal snippets. Use the existing shell/server and packaged-client workflow without adding a test-only production endpoint.

1. Prepare two roots with the same relative filename, more than 100 listing records, a timestamp disagreement, a single-valid-authority case, a parseable unsupported schema, an unavailable file and a collision fixture. Seed more than one saved-date page, including an empty Authentic. Hash source bytes before the run.
2. Start disconnected, connect and verify server-derived Today/bootstrap and retry feedback. Browse a month without import; select leap/month/year boundary dates and verify the captured zone/date groups. Verify Load more, empty/error states, independent snippet checkbox/open actions and truthful incomplete-coverage feedback using a bounded-scan fixture.
3. Choose a valid authority, verify that the old snapshot stays unchanged, then observe the new import and eligible resolved row. Reject invalid filename authority; change bytes between listing/read or resolution and verify stale feedback. Open the unsupported body with Save disabled. Confirm two roots never merge their equal relative paths.
4. Edit Authentic A, establish selection/scroll/undo history, open a source and Authentic B, then return to A through Draft and Entry. Verify the same buffer/history and that delayed loads/saves never replace another resource. Make an external synthetic change to inactive A and verify guarded reconciliation when returning.
5. Disconnect with a pending save, retain text/status, reconnect and reconcile the original operation. Exercise a synthetic save failure and confirm date/app close stays blocked with recoverable text. Start Create Empty while a source is active; verify its captured date and no-clobber behavior, then restart and find the empty date in Entry.
6. Use keyboard focus and pointer/arrow separator resizing, Settings open/close and Jump to latest. Check small-window bounds and focus/scroll restoration. Exercise active composition before tab/date/close transitions; record the observation without claiming P1-M13’s full IME/VoiceOver qualification.
7. Compare source hashes, confirm no source-body writes/deletes and record remaining provider/volume limitations. Keep fault cases needing precise delayed operations in automated tests rather than claiming manual timing proves them. Leave N11 unchecked if the packaged run is unavailable or any required result is unverified.
