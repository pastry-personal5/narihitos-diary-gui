# UX GUI

Status: Active

This document specifies the target interface from the approved original layout and engineering interaction contracts. Product scope is in [product-behavior.md](product-behavior.md); component vocabulary is in [ux-terms.md](ux-terms.md). Implementation status and evidence are recorded in the milestone records, not here; this document reflects the P1-M29 owner revisions (dark theme, Settings cards, the AI Activity widget, candidate tabs).

## Navigation and actions

Use the [Standard Layout](ux-information-architecture.md): Main Toolbar Strip, then Icon Bar, Explorer, Tabbed Editor and the AI column (the AI Activity widget above AI Chat). The toolbar shows the app title, Create Empty, Export (iCloud and Notion), Command palette, Save (while a source is active), Save status, Generate and Connection status. It shows no version text and no AI activity. The selected civil date appears in the Tabbed Editor heading and the Explorer. Disabled actions explain their missing capability or invalid state. The Icon Bar is a flat strip of icon-only SF Symbol buttons (64 px) with a hover highlight; the pressed state uses the accent fill and the accessible name stays (no visible label). Settings replaces the main content and opens with a Go back icon button (`chevron.backward`, `←` fallback) above a sidebar of four sections: Status, Writing Language, Keyboard Shortcuts and Generation. Each section uses cards. Status holds the Server, Sources and Agent profiles cards (with the result of explicit config reload) and an Advanced card that lists everything blocking Chat, Generate or saving, with a link to the pane that fixes it. Agent profiles appear in a Profile table with a status SF Symbol and a per-row Check action. Profiles are checked automatically in the background (at launch, then every 15 s doubling to a 1 h cap, per profile, for the whole session). Generation sets the candidate count (default three, range one to five). Keyboard Shortcuts is a table of Action, Original shortcuts, Current shortcuts and Info where the user edits bindings, per [keyboard shortcuts](architecture/keyboard-shortcuts.md). Writing language initially uses the Mac's preferred language, persists across sessions and applies to new AI runs. Credential editing remains in the private YAML outside the GUI; edited preferences persist in [user settings](architecture/user-settings.md).

Date selection drives a captured-timezone import of D-1/D/D+1. Snippet displays source/local-date groups, Snippet checkbox inclusion, Metadata warnings and an explicit refresh action. Newly imported eligible snippets start checked only for the selected day D (D-1 and D+1 start unchecked); re-import leaves unchanged snippets visible and preserves their selection. Focusing/opening a snippet and using its Snippet checkbox are separate actions. A Metadata warning names each parse, availability or timestamp problem; conflicting timestamps display both interpretations and an explicit authority choice; unresolved/undated snippets cannot enter generation.

The Tabbed Editor shows Markdown body text. Sources require explicit Save (toolbar Save, Command+S, the palette, or Save in the unsaved-source dialog); a file the producer-strict gate refuses, and any Ayumi file, stays readable with Save off and a reason. A failed save keeps the text; "Changed on disk" offers Discard. Authentic autosaves, and Draft/Entry navigation opens the same Editor tab/buffer. **Create Empty** immediately saves an empty Authentic file for the selected date and opens its editable buffer; it requires neither snippets nor an agent. The saved empty draft appears in Draft/Entry after restart. Disable it for an existing file or dirty/in-flight creation state and never clear existing text through this action. Candidate Editor tabs are read-only transient suggestions: Generate opens one Editor tab per candidate slot (streamed text while running) without changing the active tab, and choosing a candidate in the Explorer Draft tab activates and focuses its tab. A banner under the editor shows status, Review candidate and Discard results; discarding closes the tabs. Editor tab switching preserves editor selection/undo and pending Authentic saves. A source delete action (a trash-can bitmap icon button named "Move … to Trash") lives in the Snippet hierarchy and previews the exact snippet/validated audio set in a Confirmation dialog. Partial results list moved, failed and uncertain members; retry does not repeat completed moves.

The Trash confirmation starts on Cancel, lists the snippet and exact expected audio (including a missing state), traps keyboard focus and returns focus to its invoker when possible. Dirty source text uses Save/Discard/Cancel before preview; a cancelled or failed preview retains the existing text and selections. An expired or changed preview requires a new preview and explicit confirmation. After confirmation, the user can keep working while the session tracks the durable result independently of the dialog, row or date. Global Messages exposes inspection and renewed preview of unfinished moves after reconnect/restart; uncertainty has no automatic retry or force-clear action.

A moved source invalidates its existing import rows and inclusion choices across cached dates without rewriting snapshots or Authentic text. A new import is the refresh boundary. Clean moved-source buffers close; unsaved edits made after admission remain in an independently retained, read-only detached tab. Closing that tab still requires explicit discard, and opening a replacement source after re-import does not overwrite the detached copy. These P1-M15 client behaviors have automated component/coordinator coverage; actual Trash enablement remains tied to the [milestone evidence](archive/milestones/p1-m15/milestone-15-source-audio-trash-overview.md), including native and producer acceptance.

## Global Messages

Global Messages is a pane directly below the Tabbed Editor, within the editor column only. It lists notices and global messages to the user (save, import, export, connection, AI Activity and Completion messages, validation and errors). Messages are ordered oldest first, so the newest is at the bottom; the pane scrolls and stays pinned to the newest message unless the user has scrolled up, in which case a "Jump to latest" control appears. It opens at about 8 lines of height with small type. Each message shows time, Message severity and text; severity uses a distinct color plus icon and text label, never color alone. Messages are session-only transient UI; closing the app discards them, and they never steal focus. A Pane separator between the Tabbed Editor and Global Messages resizes its height by pointer or keyboard (visible focus, with minimum and maximum heights that keep the editor usable). Colors come from the palette below; the retained-message limit remains visual design work.

## Save, review and transition feedback

Save status shows dirty/saving/saved/failed/conflict based on the acknowledged revision, not a timer. Date change and close wait for pending Authentic saves and admitted source saves. Dirty source buffers require explicit Save or Discard; close never silently saves them. Failed saves retain the editor, offer retry and explicit discard, and block the transition. Forced process loss can lose client-only edits. Optional export failure does not change local saved status.

Generation requires at least one selected eligible snippet; otherwise Generate explains why it is disabled. It uses the Profile selector at the top of the AI Activity widget and the Generation count from Settings (default three, range one to five); profile readiness is checked in the background, with no manual generation check; runs are sequential with visible progress/cancel and independent candidate outcomes. Review flushes Authentic and verifies the captured generation baseline still matches the saved file; stale candidates require regeneration. Manual Authentic editing pauses while Review controls (per-paragraph Accept/Reject) are active; structural Markdown units are labeled. Accepted changes become saved only after acknowledgement. Rejected/pending changes do not alter the file. External changes invalidate remaining review; ending review or closing waits for admitted accepts and discards pending suggestions while preserving accepted text. Review looks like the CodeMirror unified merge view: the editor shows the saved text read-only; a pending removed or replaced paragraph is marked inline in red strikethrough, a pending insertion or replacement text appears inline in green, a gutter marker flags each changed line, and each pending change carries small Accept and Reject buttons at its end (keyboard reachable, named by an excerpt). Structural units show a label. Accepted text turns plain only after acknowledgement; rejected changes disappear. Colors are never the only cue (strikethrough, underline and labels). The exact alignment contract is in [editing and agents](architecture/editing-and-agents.md#paragraph-alignment-and-review).

Changing the selected date keeps generation running in the background for its original date and captured context. Progress/completion names that date and never switches the editor automatically. Returning to the original date exposes its session candidates; stale ones explain why regeneration is needed. The single active agent run still applies across dates. Close cancels generation and discards all app-owned transient results; date changes end the outgoing paragraph review but preserve background candidate results.

The [background AI experience](architecture/ai-job-experience.md) keeps a persistent AI Activity widget above AI Chat (not in the Main Toolbar Strip), with the Profile selectors, a summary, expandable stage/count/elapsed/Cancel details and contextual states in Draft/AI Chat. Generate/Send responds immediately with a submitting state; server admission and inference completion are distinct. Users can continue ordinary editing, autosave, navigation and Create Empty. Another AI request explains the occupied run instead of silently queueing. Completed results remain discoverable through a Results badge and one polite Completion message with View results; it never changes focus or the active editor automatically. No macOS notification or sound is used. Quiet-agent, stopping and disconnected states stay explicit, without invented percentages, time estimates or reasoning traces. If the saved entry changes during generation, the owner requires regeneration before review.

AI Chat uses the Profile selector (in the AI Activity widget) for one profile per session and sends the current active editor snapshot, including visibly identified unsaved edits. The composer is anchored at the bottom: a large flat message box and a bitmap Send button (Cmd+Enter also sends), with a context chip naming what is sent. While a Candidate tab is active, the context stays the saved Entry. Missing profiles leave editing/import available. Exceeding a context limit requires a smaller context or new chat; never silently drop messages. Closing the app discards its chat/candidates, while installed CLI/provider retention follows their own configuration/account policy.

Profile selection includes configured Codex, Claude Code, Qwen Code and Apple Foundation Models aliases. The Apple profile reports native availability, including ineligible device, Apple Intelligence disabled or model not ready; it does not request a CLI login or executable. Unavailable profiles explain their state in the Profile table and preserve editing. Selecting another profile is explicit, including after context, language or refusal errors; no automatic cloud fallback.

Export uses a selected saved revision and reports its own pending/succeeded/conflict/uncertain status. Replacing externally changed iCloud/Notion output requires a fresh explicit Export preview and confirmation; another remote change invalidates that confirmation. A local iCloud write does not claim cloud upload completion. Structural/ambiguous Notion conflicts require inspection rather than an automatic re-sort.

## Input and accessibility

The Global Messages pane is a labeled log region; new messages are announced politely without moving focus. All icon controls have text tooltips and accessible names from [UX terms](ux-terms.md). Use keyboard-operable date cells, labeled grouped checkboxes/disclosures and Pane separators with visible focus. Arrow navigation moves within the date grid using civil calendar arithmetic; Enter selects, and a skipped date gives a validation message. Preserve focus on Editor tab changes, restore dialog/palette focus to its invoker, and keep snippet focus independent of inclusion.

Factory-default shortcuts include Cmd+Shift+P (command palette) and Cmd+S (the same Save/flush action as the toolbar); all bindings are user-editable and come from the shared action registry. Do not intercept normal editing/IME composition shortcuts. Save debounce waits for composition completion. SF Symbols use the native runtime route in [platform strategy](architecture/configuration-and-exports.md#version-and-platform-strategy), with accessible text available for unsupported symbols. The GUI is dark theme only (owner, 2026-11-07) with the neutral-gray palette below, defined once as tokens in `src/styles.css`; a test rejects color literals outside the token block. Typography remains visual design work; this contract does not imply a new component library.
