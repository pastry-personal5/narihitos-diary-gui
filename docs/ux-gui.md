# UX GUI

Status: Active

This document specifies the target interface from the approved original layout and engineering interaction contracts. Product scope is in [product-behavior.md](product-behavior.md); component vocabulary is in [ux-terms.md](ux-terms.md). Implementation status and evidence belong in the [active release checklist](phase-1/milestone-32-personal-release-overview.md) and [Phase 1 changelog](phase-1/changelog.md).

## Navigation and actions

Use the [Standard Layout](ux-information-architecture.md): Main Toolbar Strip, then Icon Bar, Explorer, Tabbed Editor and the AI column (AI Chat). The toolbar shows the app title, Create Empty, Export (iCloud and Notion), Command palette, Save (while a source is active), Generate, Create Illustrated Diary, Upload Illustrated Diary to Notion, Paragraph Review, Trash Recovery and AI Activities. It shows no version text. Every toolbar action uses an icon-only custom bitmap button with a distinct app-owned PNG mask; SF Symbols and shared icons are not used for toolbar actions. Icons are 24 px within 40 px flat rounded buttons, with hover, pressed, disabled and keyboard-focus states. Accessible names and tooltips identify every action; shortcut hints and blocked reasons remain in tooltips. Conditional Save follows the same rule. The selected civil date appears in the Tabbed Editor heading and the Explorer. Disabled actions explain their missing capability or invalid state. The Icon Bar is a flat strip of icon-only bitmap buttons (32 px, dimmed until hovered) with a hover highlight; the pressed state uses the accent fill and the accessible name stays (no visible label). Settings replaces the main content in the same window; its categories and cards are described below.

Date selection drives a captured-timezone import of D-1/D/D+1. Snippet displays a compact table (Include checkbox, Ayumi/Narihito icon, name, state icons, Details) and a Details overlay that shows state, errors, metadata warnings and the file text with its metadata header. The overlay has a custom bitmap Close button at the top right beside the title, with initial focus, a tooltip and Escape dismissal; closing restores focus to the invoker. Snippet checkbox inclusion and refresh remain explicit actions. Newly imported eligible snippets start checked only for the selected day D (D-1 and D+1 start unchecked); re-import leaves unchanged snippets visible and preserves their selection. Focusing/opening a snippet and using its Snippet checkbox are separate actions. A Metadata warning names each parse, availability or timestamp problem; conflicting timestamps display both interpretations and an explicit authority choice; unresolved/undated snippets cannot enter generation.

The calendar header centers the month between custom bitmap Previous month and Next month chevron buttons, with tooltips, accessible names and disabled states at calendar boundaries.

Explorer view buttons retain tooltips, accessible names and selected state; no active-view title (such as "Date tab" or "Draft tab") appears below the icons.

The Tabbed Editor shows Markdown body text without a visible “Tabbed Editor” heading; its accessible region name remains. Passive read-only, load-error and source notices appear in Global Messages; actionable save-conflict recovery stays beside the editor. Sources require explicit Save (toolbar Save, Command+S, the palette, or Save in the unsaved-source dialog); a file the producer-strict gate refuses, and any Ayumi file, stays readable with Save off and a reason. A failed save keeps the text; "Changed on disk" offers Discard. Authentic autosaves, and Draft/Entry navigation opens the same Editor tab/buffer. **Create Empty** immediately saves an empty Authentic file for the selected date and opens its editable buffer; it requires neither snippets nor an agent. The saved empty draft appears in Draft/Entry after restart. Disable it for an existing file or dirty/in-flight creation state and never clear existing text through this action. Candidate Editor tabs are read-only transient suggestions: Generate opens one Editor tab per candidate slot (streamed text while running) without changing the active tab, and the Explorer Draft tab presents candidates in a four-column table matching the Snippet tab table: Number, Style label, bitmap Info and bitmap Open in Tabbed Editor. Number runs from one across the visible candidates; Style label follows each candidate's generation style. Info opens a dismissible Style description dialog and returns focus on close. Open in Tabbed Editor activates and focuses the existing read-only candidate tab or reopens a closed tab with its retained content; unavailable results have a disabled button with a tooltip and screen-reader reason. Background streaming/completion updates keep deliberately closed candidate tabs closed. Opening respects text composition before creating a tab. The Style description modal makes the application background inert until dismissed. Candidate status, stale-baseline and error messages go to Global Messages; a control strip under the editor offers Review candidate and Discard results; discarding closes the tabs. Editor tab switching preserves editor selection/undo and pending Authentic saves. A source delete action (a trash-can bitmap icon button named "Move … to Trash") lives in the Snippet hierarchy and previews the exact snippet/validated audio set in a Confirmation dialog. Partial results list moved, failed and uncertain members; retry does not repeat completed moves.

The Trash confirmation starts on Cancel, lists the snippet and exact expected audio (including a missing state), traps keyboard focus and returns focus to its invoker when possible. Dirty source text uses Save/Discard/Cancel before preview; a cancelled or failed preview retains the existing text and selections. An expired or changed preview requires a new preview and explicit confirmation. After confirmation, the user can keep working while the session tracks the durable result independently of the dialog, row or date. Trash Recovery in the Main Toolbar Strip opens a dedicated dialog for inspection and renewed preview of unfinished moves after reconnect/restart; uncertainty has no automatic retry or force-clear action.

A moved source invalidates its existing import rows and inclusion choices across cached dates without rewriting snapshots or Authentic text. A new import is the refresh boundary. Clean moved-source buffers close; unsaved edits made after admission remain in an independently retained, read-only detached tab. Closing that tab still requires explicit discard, and opening a replacement source after re-import does not overwrite the detached copy. Trash availability follows the source-format and validated-audio guards in [sources and dates](architecture/sources-and-dates.md#related-audio-and-trash); text-only snippets do not support Trash.

## Settings

Settings opens on Status. A Go back icon button (`chevron.backward`, `←` fallback) sits above the Settings sidebar and returns to Main. The selected category displays its settings in cards.

The [canonical category and card inventory](ux-terms.md#settings-categories-and-cards) defines the sidebar order. Server is first in the sidebar; Status remains the initial page.

Server keeps automatic connection and reconnection running in the background; Connect is disabled while connecting. Configuration reload and its result belong to Server.

Sources reveals the folder containing the active server configuration file in macOS Finder. Reveal configuration folder in Finder is disabled while disconnected and while opening Finder. An opening state gives immediate feedback; failure shows an actionable message in the card. Source configuration and credentials are edited in the private YAML outside the GUI; after editing, use Reload configuration in Server. Settings does not display private configuration paths or contents.

Chat profile, Generation profile and Paragraph Review profile choices are independent and remain selected when Settings closes and reopens during the session. Chat and Generation selectors are disabled while their corresponding controller is running or has no profiles to offer. Paragraph Review is disabled when no profiles are available; changing its profile invalidates any active paragraph suggestion. Profile selectors live in AI Agents; Main's AI Activities dialog displays activity and results. Agent profiles appear in the Profile table with a status SF Symbol, reason and per-row Check action. Background checks continue for the whole session, starting at launch and then every 15 s doubling to a 1 h cap per profile; transient busy checks retry at the base interval.

Writing Language initially uses the Mac's preferred language, persists across sessions and applies to new AI runs. Generation saves the candidate count for new requests. Keyboard Shortcuts follows the [keyboard shortcuts contract](architecture/keyboard-shortcuts.md). Edited preferences persist in [user settings](architecture/user-settings.md).

## Trash Recovery

Trash Recovery in the Main Toolbar Strip opens a modal dialog in the current application window. It is available while disconnected so users can read the recovery guidance. The dialog defaults to 960 × 740 CSS pixels, bounded by the viewport with 24 px outer clearance. A fixed header keeps its title and top-right Close button visible above scrollable content; guidance cards use two columns when space permits and one on smaller windows. Close receives initial focus, Tab stays inside the dialog, and Close or Escape returns focus to the toolbar button.

The Current situation section explains whether the server is disconnected, discovery is running, discovery failed, no unfinished moves were found, or saved moves are available to inspect. Disconnection directs users to Settings > Server to connect; read-only or unavailable storage permits result inspection but blocks moving remaining files. A failed discovery warns that the list may be incomplete and offers another check. Check unfinished moves refreshes saved operations; it is disabled while disconnected or already checking. Next unfinished moves loads another page when available. These checks do not initiate a new move to Trash.

Each saved move identifies its source and status, with Inspect opening its file-by-file result. Guidance explains that the snippet and related audio move separately and that closing a view does not cancel a requested operation. Available actions depend on the saved outcome:

| Situation                                     | What the user can do                                                                                                                                                                                                                            |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Checking confirmation / Checking saved result | Wait for the saved outcome; use Check again after a failed request, or Check saved result in the result dialog while connected.                                                                                                                 |
| Needs confirmation                            | Inspect the moved, missing and remaining files. When eligible files remain and storage is writable, choose Preview remaining files, review the exact list and explicitly confirm. Refresh an expired preview; completed moves are not repeated. |
| Outcome uncertain                             | Inspect the original location and macOS Trash in Finder to establish what happened. No automatic retry or forced clearing is available.                                                                                                         |
| Completed                                     | Inspect the per-file outcomes or Dismiss the completed move from the list. Dismiss does not restore files.                                                                                                                                      |

Only one recovery or result/confirmation dialog is shown at a time. Closing a result or cancelling a remaining-files preview returns to Trash Recovery. Guidance also explains that restoring files is a Finder action: open macOS Trash and use Put Back when available. Trash Recovery itself does not restore files.

## Global Messages

The toolbar has no save-status text; save notifications appear here. Generation configuration (candidate count, locale and selected-snippet scope), blocked reasons and adjacent-date warnings appear in Global Messages when they change, with no inline generation message strip. Retry/cancel controls remain available beside the editor. Global Messages is a pane directly below the Tabbed Editor, within the editor column only. It lists notices and global messages to the user (save, import, export, connection, AI Activity and Completion messages, validation and errors). Trash operation notices may direct users to Trash Recovery; unfinished-move checks, operation lists and recovery actions belong in its dialog. Messages are ordered oldest first, so the newest is at the bottom; the pane scrolls and stays pinned to the newest message unless the user has scrolled up, in which case a "Jump to latest" control appears. It opens at about 8 lines of height with small type. Each message shows time, Message severity and text; severity uses a distinct color plus icon and text label, never color alone. Messages are session-only transient UI; closing the app discards them, and they never steal focus. A Pane separator between the Tabbed Editor and Global Messages resizes its height by pointer or keyboard (visible focus, with minimum and maximum heights that keep the editor usable). The pane retains the latest 500 messages and reports how many older session messages were removed. Color tokens are defined in `src/styles.css`.

Each profile in Settings → AI Agents has a saved, default-on **Show progress using Global Messages** checkbox. Generate, Chat and Paragraph Review use the running profile’s setting to report request/response stages every two seconds, including preparation and unchanged waits. Stale or disconnected observations report status unavailable until refreshed. Reporting stops when work finishes; disabling periodic progress preserves completion, warnings and errors. Persistence and editing guards are defined in [user settings](architecture/user-settings.md#ai-agent-progress-messages).

## Save, review and transition feedback

Save status shows dirty/saving/saved/failed/conflict based on the acknowledged revision, not a timer. Date change and close wait for pending Authentic saves and admitted source saves. Dirty source buffers require explicit Save or Discard; close never silently saves them. Failed saves retain the editor, offer retry and explicit discard, and block the transition. Forced process loss can lose client-only edits. Optional export failure does not change local saved status.

Generation requires at least one selected eligible snippet; otherwise Generate explains why it is disabled. It uses the Generation profile selector in Settings → AI Agents and the Generation count from Settings (default three, range one to five); profile readiness is checked in the background, with no manual generation check; runs are sequential with visible progress/cancel and independent candidate outcomes. Review flushes Authentic and verifies the captured generation baseline still matches the saved file; stale candidates require regeneration. Manual Authentic editing pauses while Review controls (per-paragraph Accept/Reject) are active; structural Markdown units are labeled. Accepted changes become saved only after acknowledgement. Rejected/pending changes do not alter the file. External changes invalidate remaining review; ending review or closing waits for admitted accepts and discards pending suggestions while preserving accepted text. Review looks like the CodeMirror unified merge view: the editor shows the saved text read-only; a pending removed or replaced paragraph is marked inline in red strikethrough, a pending insertion or replacement text appears inline in green, a gutter marker flags each changed line, and each pending change carries small Accept and Reject buttons at its end (keyboard reachable, named by an excerpt). Structural units show a label. Accepted text turns plain only after acknowledgement; rejected changes disappear. Colors are never the only cue (strikethrough, underline and labels). The exact alignment contract is in [editing and agents](architecture/editing-and-agents.md#paragraph-alignment-and-review).

Changing the selected date keeps generation running in the background for its original date and captured context. Progress/completion names that date and never switches the editor automatically. Returning to the original date exposes its session candidates; stale ones explain why regeneration is needed. The single active agent run still applies across dates. Close cancels generation and discards all app-owned transient results; date changes end the outgoing paragraph review but preserve background candidate results.

The [background AI experience](architecture/ai-job-experience.md) uses AI Activities in the Main Toolbar Strip to open a spacious modal with stage/count/elapsed/Cancel details and contextual states in Draft/AI Chat. The [Status line](#status-line) summarizes activity across dates and Settings; stale observations never claim a run is still active. Generate/Send responds immediately with a submitting state; server admission and inference completion are distinct. Users can continue ordinary editing, autosave, navigation and Create Empty. Another AI request explains the occupied run instead of silently queueing. Completed results remain discoverable through a Results badge and one polite Completion message with View results; it never changes focus or the active editor automatically. No macOS notification or sound is used. Quiet-agent, stopping and disconnected states stay explicit, without invented percentages, time estimates or reasoning traces. If the saved entry changes during generation, the owner requires regeneration before review.

Export uses a selected saved revision and reports its own pending/succeeded/conflict/uncertain status. Replacing externally changed iCloud/Notion output requires a fresh explicit Export preview and confirmation; another remote change invalidates that confirmation. A local iCloud write does not claim cloud upload completion. Structural/ambiguous Notion conflicts require inspection rather than an automatic re-sort.

## Caret paragraph review

The Paragraph Review bitmap action in the Main Toolbar Strip reviews the caret paragraph in the focused editable Authentic buffer, without requiring a Candidate. It uses the independent Paragraph Review profile in Settings → AI Agents and an isolated transient conversation that preserves the user’s AI Chat. The request identifies the target paragraph and supplies eligible D-1/D/D+1 snippet context under the [paragraph review contract](architecture/paragraph-review.md).

A suggestion appears below the paragraph with Accept and Reject at the top right. Accept rechecks the captured full buffer and editability, then makes an undoable editor transaction followed by normal autosave. Reject removes only the suggestion. Navigation, profile/language changes or stale text invalidate it. Candidate review remains a separate saved-revision workflow; the two review modes are mutually exclusive.

## Status line

The bottom status line stays visible in Main and Settings. It presents operational AI activity and unread results, plus independent Generate ready, Review ready and Chat ready labels when the corresponding action is eligible. Review ready refers to caret paragraph review. Settings → Status Line saves each readiness label’s visibility, defaulting to visible; hiding a label does not hide operational activity. Items align left with a 16 px gap and wrap on narrow windows. Foreground colors distinguish readiness and activity states while text communicates the state independently. See [status line settings](architecture/user-settings.md#status-line-indicators).

## AI Activities

AI Activities in the Main Toolbar Strip opens a 960 × 740 CSS pixel modal bounded by the viewport with 24 px clearance. The header matches Trash Recovery: a muted 12 px “AI Agents & results” eyebrow above the 26 px title, a panel background and a rounded top-right Close button. Both dialogs share header/body spacing and rounded guidance cards. The fixed header stays visible above scrollable guidance and activity cards. Close receives initial focus; Tab stays inside; Close or Escape returns focus to the invoker. Closing keeps AI work running. AI Chat fills the AI column.

Plain-language guidance explains waiting, cancellation, partial results and session storage. Bitmap (i) buttons open separate explanation overlays with Close/Escape behavior and focus return to the info button. View results, Cancel AI run, Dismiss result indicator, Discard generation results and Reconnect live here. Successful View results closes the dialog after guarded navigation succeeds; refused navigation preserves the dialog and unread state. Completion feedback remains active in Global Messages while the dialog is closed. Profile choices remain in Settings → AI Agents.

## Input and accessibility

Draft and Entry use distinct page-and-pencil and checked-page bitmap buttons with tooltips, accessible names and pressed states; they retain the shared editor buffer. Global Messages uses a down-arrow-to-line bitmap button for Jump to latest, shown when scrolled away from the latest messages.

The Global Messages pane is a labeled log region; new messages are announced politely without moving focus. All icon controls have text tooltips and accessible names from [UX terms](ux-terms.md). Use keyboard-operable date cells, labeled grouped checkboxes/disclosures and Pane separators with visible focus. All main-window Pane separators use a one-pixel neutral divider centered in a six-pixel resize track, becoming a two-pixel accent line on hover, keyboard focus or drag. Vertical and horizontal separators share this treatment; adjacent pane borders do not double the divider. Arrow navigation moves within the date grid using civil calendar arithmetic; Enter selects, and a skipped date gives a validation message. Preserve focus on Editor tab changes, restore dialog/palette focus to its invoker, and keep snippet focus independent of inclusion.

Factory-default shortcuts include Cmd+Shift+P (command palette) and Cmd+S (the same Save/flush action as the toolbar); all bindings are user-editable and come from the shared action registry. Do not intercept normal editing/IME composition shortcuts. Save debounce waits for composition completion. SF Symbols use the native runtime route in [platform strategy](architecture/configuration-and-exports.md#version-and-platform-strategy), with accessible text available for unsupported symbols. The GUI is dark theme only. `src/styles.css` is the authority for color token values, including chat and status colors; a test rejects color literals outside its token block. Use the system font stack defined there.

Native keyboard, Korean IME, Editor tab/focus/undo preservation, Pane separator resizing, long documents and large snippet groups require WKWebView observations; mocks cannot establish native behavior. Automated role/name tests cover accessible names and ordering. Native observation procedures and exemptions are recorded in the [by-human guide](phase-1/milestone-32-by-human-tests.md); required automated/artifact acceptance is defined by the [release policy](phase-1/milestone-32-personal-release-overview.md#acceptance-policy-owner-update-2026-11-09).

## Command palette overlay

The toolbar button toggles the non-modal search overlay below the Main Toolbar Strip; its shortcut opens it. The [keyboard contract](architecture/keyboard-shortcuts.md#command-palette-overlay) defines matching, ranking, execution guards, composition and focus behavior.

## AI Chat

AI Chat uses the Chat profile selector (in Settings → AI Agents) for one profile per session and sends the current active editor snapshot, including visibly identified unsaved edits. AI Chat opens at a 480 px default width and remains resizable. The composer is anchored at the bottom: a large flat message box and a bitmap Send button (Enter sends; Shift+Enter adds a new line; no shortcut hints appear in the composer), with a context chip naming what is sent. While a Candidate tab is active, context comes from the Authentic buffer, including identified unsaved edits; the Candidate text is not sent. Missing profiles leave editing/import available. Exceeding a context limit requires a smaller context or new chat; never silently drop messages. Closing the app discards its chat/candidates, while installed CLI/provider retention follows their own configuration/account policy.

AI Agents are the configured providers used by AI Chat, Generate and Paragraph Review. Profile selection includes configured Codex, Claude Code, Qwen Code and Apple Foundation Models aliases. The Apple profile reports native availability, including ineligible device, Apple Intelligence disabled or model not ready; it does not request a CLI login or executable. Unavailable profiles explain their state in the Profile table and preserve editing. Selecting another profile is explicit, including after context, language or refusal errors; no automatic cloud fallback.

AI Chat accepts `/clear` as a local command to clear context and start a fresh conversation, without sending the command to an agent. It is unavailable during an active reply. The composer keeps its accessible Message label with a dimmed native “Chat with AI” placeholder that disappears immediately when typing, and no empty-message warning; there is no New chat button.

AI Chat context appears at the top left inside the composer, above the text input, in a thin-bordered box with a custom bitmap document icon followed by the current context label. It updates with document selection and unsaved edits; no selection shows No document. Long labels wrap within the composer.

The AI Chat Send button uses a thin white bitmap up arrow centered in a filled blue circle, with a transparent outer button surface. Hover/press feedback stays inside the circle; disabled opacity and keyboard focus remain visible.

AI Chat uses `--ai-chat-bg` throughout its column and pane, `--ai-chat-input-bg` for its composer and `--ai-chat-placeholder` for placeholder text; token values live in `src/styles.css`.

## Illustrated diary

Create Illustrated Diary is a distinct bitmap ToolbarButton and a shared Command palette action, without a default shortcut. Its tooltip carries the same disabled reason as the palette. It targets the working date’s saved Authentic and uses the Generation profile and Writing Language. Save settling happens before admission; no render-duration editor lock is introduced.

The dedicated Illustrated Explorer tab has an independent date catalog, loading, empty, failure and Refresh states. Opening a listed day uses existing date/save guards, then selects its Illustrated resource. The resource’s date/kind label distinguishes it from Authentic, Source and Candidate tabs. The viewer shows a Read-only heading and version-bound Delete action, with no save/review/export controls. Reading selection, copy and find remain available; checkbox/table/document changes are refused. The toolbar keeps ordinary Generate and other actions subject to their own guards.

Generated-photo widgets retain alt text, defer bridge reads until viewport demand and expose Retry after failure. Photo dimensions reserve layout and use fluid width. No lightbox, gallery or prompt editor is included. Closing a tab or leaving its viewport releases owned photo URLs/allocations; inactive/disconnected resources issue no new photo reads. A retained offline copy is labelled stale.

AI Activities uses the existing details, Cancel and status-line surfaces for Illustrated text/photo/stopping/terminal progress. A completed result opens automatically only while its originating day is still selected; another day receives a Global Message. Successful replacement updates an already-open resource without selecting a background day. Source-age notices belong quietly in Global Messages, once per observed source/version change. Failed or cancelled work does not replace the previous publication.

Delete uses ModalDialog with Cancel as initial focus and the existing focus trap/restoration. Confirmation carries the viewed version; stale confirmation reloads and requires a new decision. Image engines is a card within Settings > AI Agents, not a new Settings category: show label/ID, effective selection, readiness/reason, Check and checking state. Check readiness automatically on connection and when opening AI Agents, keep the interface responsive, and report problems in Global Messages without repeating unchanged warnings. No engine prompt, path or credential is displayed. Existing focus indicators and reduced-motion rules apply to all new controls.

### Illustrated Notion upload

`illustrated.upload.notion` is the shared toolbar/palette action, with no default shortcut and a distinct original PNG mask. It captures selected date and published version once. Availability explains disconnected/storage/root/missing-entry/conflicting-operation states independently of the active editor, saved Authentic content or AI readiness. Working status offers Stop upload; previews and uncertain outcomes say Notion day page. Global Messages narrate hierarchy, photo upload, verification and old-body cleanup without changing focus/date on completion. Cancellation and partial cleanup never claim rollback; uploaded files and created pages may remain, and removed old body blocks are restorable from Notion trash.
